# 移动部件的接触表示

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 轮胎外观有体积，但侧面、路缘或沟渠接触未被当前表示覆盖。
- 增加采样或更复杂形状后出现卡边、抖动、意外弹起或成本增长，需要验证是否值得。

## 先确认的输入

玩法要求的接触方向、轮胎尺度、地形集合、现有采样/碰撞形状、物理更新时间、悬架/吸震/摩擦及转向辅助设置。先说明物理需求，不由圆形网格推断具体 collider/API。

## 分步机制

1. 以平地、路缘、侧面沟渠复现缺失的接触，区分外观问题与实际覆盖问题。
2. 明确需要底部、侧面还是其他方向接触，再选候选表示。DWFm4_eDlCm 的单线、轮周多线和圆柱是替代版本，不是三层必须叠加的升级链。
3. 保持轮胎尺度、地形、速度、吸震、摩擦及辅助不变比较所需接触覆盖；不要把所有版本已有吸震算作圆柱方案新增收益。
4. 同时测稳定性与物理更新成本，保留满足需求的较简单方案。采样数量、碰撞 API 和更新策略需项目实现验证，不从绿色线框反推 sweep 或刚体方法。
5. 将[接触响应诊断](../../gameplay-contact-response/SKILL.md)分开记录；若另改网格损伤、弹性或控制映射，用独立实验，不让多项改动掩盖碰撞回归。

## 适用限制

- 来源仅展示三个版本和新版 V 形沟渠侧接触；没有射线数量、圆柱 API、摩擦/悬架参数、代码或性能测量。
- 作者称操控略有改善不是量化结果；撞击掉轮是未来设想，不是本技能已证功能。
- 复杂形状不必然更好，接触表示变化是物理规则变更，不是模型美化。

## 验收

- [ ] 相同初始条件下覆盖平地、路缘与侧面沟渠，记录漏接触、卡边、抖动和非预期弹起。
- [ ] 高速、斜向及重复接触仍符合设计；不能以单段 V 沟展示代替项目地形回归。
- [ ] 记录物理更新成本与预算，比较时保持吸震、摩擦、控制辅助一致。
- [ ] 视觉轮胎与真实接触关系可解释；若为玩法采用简化表示，明确其边界而非以网格更圆证明正确。

## 组合而不复制

- 轮胎接触形状明确但承载面本身需要弯曲/压缩时，转到[交互承载面](../../gameplay-deformable-support/SKILL.md)；轮胎覆盖和表面结构分别验收。

- [车辆转向辅助](../../gameplay-steering-assistance/SKILL.md)：输入映射是另一工作流。
- [形变与接触响应分离](../../gameplay-contact-response/SKILL.md)：不由变形画面推断碰撞算法。

攀爬角色需要汇总多表面命中位置/法线以保持附着时，转到[窄边缘支撑估计](../../gameplay-surface-adhesion/SKILL.md)。它与本页共享覆盖检查原则，但不由轮胎接触表示代替角色支撑状态。
