# 几何边界与离散事件触发对齐

本流程诊断事件何时因几何关系成立而触发。来源提供作者替换触发方案的说明及调试/错误示例，未独立验证新版精确触发瞬间；所有数学实现与验收必须在项目中明确，不能由两个点名补造公式。

## 触发条件

- 木材等移动物体已经经过工具，却仍未发生切断/分离，或事件在尚未到达有效边界时提前发生。
- 大范围 trigger 的进入/离开与真正操作位置不一致，需要检查规则几何而非加快表现动画。

## 先确认的输入

操作边界的定义、工具与物体的实际几何参照、坐标空间、运动方向/范围、事件前后对象状态、现有触发规则与更新时钟。若要做数学检查，必须补齐构造的向量、参考轴/平面、单位和比较语义；没有这些信息只做诊断，不提供 dot-product 公式、符号或阈值。

## 分步机制

1. 分别记录物体到达几何边界、权威切断事件及可见分离的时刻/位置，定位是判定过迟，还是判定已发生但动画/生成延迟。不从“看着晚”直接调动画速度。
2. 可视化原 trigger 与有效参照。DX1yDNMN4-C 可见锯片中心/木材末端附近彩点、连线和触发区，作者说用与这两处相关的 dot-product check 替换宽泛 trigger；这不是完整的向量构造或比较公式。
3. 按项目真实操作含义选择触发条件，并先声明几何和状态约束。两个位置本身不足以定义有明确触发意义的点积；需知道向量怎样构造、相对哪个方向/边界比较及是否需要其他范围限制，不能从彩点或名称猜正负号。
4. 区分条件当前成立与一次经过边界的事件。按项目定义待触发/已触发及允许重置的状态，单独处理反向、暂停、重新送入和传送；这些防重复/交叉检测策略是实施建议，来源未公开。
5. 将成立事件传给实际切断/结果流程，再核对显示与事件一致。网格怎样切开、物理碎片怎样生成不由本页提供；不要把粒子、木材已分离或 WRONG CUT 画面当成新版精确性证明。
6. 在同几何和运动条件下对比原方案与候选，改变送入速度、木材长度和更新步长分别检查早/晚误差、漏触发和重复触发。未测之前只称作者方案，不称延迟已经消除。

## 来源与适用限制

- 作者明确报告旧切断过晚并称新检查时机正确；观测有锯切过程、编辑器彩点/连线和标为 WRONG CUT 的分离位置。WRONG CUT 是错误示例，不能当修正版；稀疏截图未独立核新版准确切断帧。
- dot product 的向量定义、参考轴/平面、符号、阈值、范围限制、穿越处理及执行时序未知；没有源码审计或公式验证。不能承诺单个点积对任意三维工具/物体都足够。
- 画面 0.52 m/s 与 2155 RPM 是顺带 HUD 读数，不是推荐/已核配置参数，不作为本页配方。无受控同输入旧新 A/B、数值精度/性能或音频测试。
- 本页调整事件判定关系，可能影响真实切断/产物规则，不是纯特效；刀具实体接触、安全距离、网格切割和碎片物理须由各项目另行实现验证。

## 验收

- [ ] 用可视化参照同时记录边界位置、权威事件和可见分离，区分规则与表现延迟；测试结论不来自作者“现在正确”的陈述。
- [ ] 给出项目明确的向量/坐标/比较语义，再覆盖边界两侧、不同物体长度/姿态和适用范围；未满足前不编公式或通用阈值。
- [ ] 慢速/高速、更新步长变化、一次跨过边界及停在边界时，不漏触发或每帧重复触发；重复进入是否允许由项目状态定义。
- [ ] 反向、暂停恢复、传送、重载/重生及工具/物体销毁后，已触发与重新待触发状态正确；不在未授权方向产生切断或重复产物。
- [ ] 分离表现、真实对象终态和产物一次性处理一致，切割几何/碰撞另验；保留原方案对照和测量结果，不写“点积天然零延迟”。
