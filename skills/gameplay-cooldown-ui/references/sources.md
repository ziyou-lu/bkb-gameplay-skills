# 冷却时钟与就绪反馈

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 显示已恢复却仍不能用，或真实技能就绪但界面没有确认。

## 先确认的输入

真实冷却截止/剩余时间、可用条件、项目时钟、重置/取消事件与显示生命周期。

## 分步机制

1. 先确定时钟是否受暂停/慢动作影响，UI 订阅真实剩余时间和可用条件，不另跑独立假倒计时。
2. 选择扫过填充、变暗及倒计时的组合；取整与最小显示单位不得误报提前就绪。
3. 真实状态先变可用，再播放短恢复确认；动画不能延迟后续合法操作。
4. 处理冷却重置、缩短/延长与界面关闭重开，保持显示重新读取权威时间，不积累旧动画。

## 适用限制

- 来源展示扫过填充、变暗、倒计时和恢复，但未验证真实冷却时钟；恢复动画参数未知。
- 所有暂停、并发和时间修改处理都是迁移验收，不是作者代码已验证。

## 验收

- [ ] 极短/极长冷却、显示取整及刚好就绪边界不误报。
- [ ] 重置、暂停/慢动作与切场后和真实可用性一致；恢复确认不阻挡连续操作。

## 组合而不复制

- [资源读数](../../gameplay-resource-ui/SKILL.md)：法力/体力值是另一输入
- [按住交互](../../gameplay-contextual-ui/SKILL.md)：保持/释放不是冷却
