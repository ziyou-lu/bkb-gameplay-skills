# 翻转视角下的重力方向线索

本入口让玩家辨认世界方向，不负责矫正镜头姿态。来源支持小滴画面和作者的脚步/重力说明，没有独立轨迹、概率或感知测试；工程步骤与验收需要目标项目验证。

## 触发条件

- 角色能沿墙或天花板移动，画面和角色朝向不再能直接表示实际向下方向。
- 需要细微的方向参照，但不能为此强制锁定世界朝上镜头或改变玩法重力。

## 先确认的输入

权威重力方向及其变化规则、真实脚步事件、角色与相机朝向、允许显示的方向信息、提示生成与清理状态。明确“实际向下”与角色局部下方向/支撑面法线的区别；粒子生命周期、速度、大小、坐标空间和碰撞处理由项目配置，来源未给实现。

## 分步机制

1. 在地面、墙面和天花板记录相同运动，先确认玩家需要读出的世界方向，而不是目标位置、落地强度或下一可走路线。
2. 将线索绑定合适的事件，避免把每帧接触当脚步。DUdJFcvDywX 作者选择每步有 50% 概率生成极小粒子；这是候选示例，不保证短时间内一定出现，也不是通用最佳密度。
3. 让提示运动反映项目真实重力，避免跟着角色局部下方向走。作者称小滴随重力落下；实际仿真空间、初速度、重力大小和完整轨迹未核，需在项目中可视化检查，不能仅按屏幕向下发射。
4. 分别检查脚步稀疏/静止和连续移动的覆盖。若没有足够线索，先记录这一事件触发方案的局限，再按项目选择其他参照或提示策略；来源没有证明静止时也清楚，不能擅自宣称已有保底提示。
5. 在不同相机朝向和背景下比较可读性与杂乱，确保线索足够细微但不至于看不见。重力变化、相机/角色切换和切场时按项目清理或更新，避免旧方向残留造成误解。
6. 分开验收方向正确、玩家能识别与不干扰动作。粒子存在不等于辨认成功，更不证明减少晕动或解决迷向；不得顺带改角色重力、移动速度和镜头控制。

## 来源与适用限制

- 实见倒挂角色示意、Floor/向下解释，以及不同朝向的上下双视图中脚边/下方小白滴。大箭头属于视频解释层，未证明是游戏 UI；双视图不是旧新版 A/B。
- 每步 50% 与受重力下落来自作者说明；稀疏画面未独立核完整加速轨迹、逐脚事件时点或统计概率，不把粒子旁的深色足迹当同一机制。
- 未核寿命、初速度、大小、重力值、坐标空间、发射器附着、碰撞行为、平台和性能；没有源码、感知或舒适度实验，音频未核听。
- “实际向下”不等于所有可见表面都是可站地面，也不提供寻路或安全落点判断；本页只是世界方向参照，不是完整重力或相机系统。

## 验收

- [ ] 地面、墙面、天花板与旋转相机下，提示沿声明的真实重力方向变化，不误跟角色局部下方向或固定屏幕轴；若重力可变，另测切换中的旧提示。
- [ ] 采用每步触发时，静止不持续误发；低步频和随机长空窗的可见性有记录，多步高频也不造成遮挡。50% 不被当作短窗口可靠性保证。
- [ ] 在不同背景、视距和相机姿态下，让玩家实际指出向下方向，比较无提示和候选提示；结果未测前不写改善率或“减少眩晕”。
- [ ] 切场、传送、角色/相机切换及粒子过期后无误导残留；配置只改显示，不改变物理重力、接地判定或镜头控制权。
- [ ] 提示不遮挡角色、关键物和危险路径，不被误认成攻击、可拾取物或路线；生命周期/密度/性能按目标平台测量。

## 组合而不复制

- [表面感知相机 up](../../gameplay-surface-camera-up/SKILL.md)改变基础相机朝向参考；本页即使镜头不动，也只表达世界重力方向。
- [落地反馈](../../gameplay-landing-feedback/SKILL.md)确认一次着地及强度，不以粒子外观接管方向参照。
- [世界目标发现性](../../gameplay-world-readability/SKILL.md)指出资源/物体位置，不负责世界向下方向。
- [世界内操作指示](../../gameplay-worldspace-indicators/SKILL.md)校对操作目标投影与深度，不求解这里的方向辨认。
