# 工具动作与身体持握协调

本流程处理一次工具动作中手、工具与身体的协调，不是方向 sprite 组合。来源直接展示双手/工具与编辑器引导，脊柱、头和膝的贡献主要为作者说明，不能将不可见关节或展示代码当已验证实现。下面的步骤和验收是迁移建议，不是来源已执行的工程测试。

## 触发条件

- 第一人称斧头等工具摆动只带动手，身体参与不足或持握显得脱节。
- 双手、工具路径和身体姿态各自变化，造成滑握、交叉、视角晃动或接触位置不一致。
- 若只是俯视/侧视像素角色瞄准时分件外形错误，改用方向瞄准与分件姿态入口。

## 先确认的输入

已定义的工具动作意图/轨迹、双手持握锚点、角色姿态/rig 可控通道、目标高度与空间、第一人称视角约束及真实攻击/工具事件。先区分视觉工具轨迹、持握约束、身体驱动和实际接触判定；输入映射、IK 求解器/权重、骨骼绑定及动作曲线都需项目提供。

## 分步机制

1. 记录原手部独动与目标动作，检查问题在持握、路径、身体参与还是可见镜头反馈。DW1b54bDW3M 明确标注 ONLY THE HANDS MOVED，后续有双手握斧编辑器和第一人称姿态演示，未建立全身逐关节受控 A/B。
2. 先明确工具路径和双手持握关系，再检查可用约束。作者称使用 IK，画面有彩点/引导轨迹，但不公开完整求解器；不能从 gizmo 或“FOLLOW PHYSICALLY”推断力学模拟或具体末端修正算法。
3. 按项目动作设计评估身体参与。作者说明脊柱旋转、头部 roll 与膝弯共同加入；这些只是候选通道，不是通用角度、顺序或必须全开的清单。逐项检查驱动权，避免工具、手部和躯干各自修改同一姿态产生冲突。
4. 在动作范围内核对握点和工具接触意图，改变目标高度/距离并检查现有动作约束。手看似握稳不证明刀刃判定或伤害正确；真正切断/命中事件仍由项目权威规则决定。
5. 对头部/视角参与单独限制并评估，区分角色头姿态与实际相机移动。作者头 roll 说明不证明具体相机绑定，也不证明舒适；必要时提供项目允许的减弱方案，不让姿态优化夺走观察控制。
6. 用相同输入比较手部独动与候选协调动作，检查重复挥动、取消、目标变化与状态恢复。保持原攻击/工具规则，结果不以“感觉对了”替代持握、接触和可用性验收。

## 来源与适用限制

- 实见双手握斧、编辑器彩色点/轨迹及后段第一人称抬起/倾斜姿态。脊柱、头和膝的贡献来自作者正文/字幕，第一人称视角没有独立展示每个关节幅度；不声称膝弯已视觉逐项验证。
- 作者称 dynamic、IK、biomechanics 或 physically，不证明真实物理、动作捕捉或解剖正确性。代码面板未完整读/执行，OH I FIXED THAT 所指 bug 未核，不补成端点或朝向求解修复。
- 输入映射、目标选择、IK 类型/权重、骨骼参数、摆动曲线、伤害和接触时机均未知，没有数值配方、性能或舒适度测试；音频未核听。
- 较早 DWJ0q-WjYEd 仅为方案背景：作者在 Animation Blend 与 Full IK 间征询选择，文字提鼠标控手/速度影响伤害；鼠标上箭头、抬斧和编辑视图可见，但伤害响应未测。不能把早期规则继承到本页较晚来源，也不宣布 IK 胜过动画。
- 本页不是任意角色全身动画工具包，也不要求每种工具都加入头/膝运动；身体参与不自动改善操控，完整 solver 与实际玩法变更须独立设计验证。

## 验收

- [ ] 同动作范围内双手持握持续对应工具，不出现项目不可接受的滑握/穿插/交叉；记录原版与候选的匹配输入对照。
- [ ] 不同目标高度/距离、动作反向/重复、取消和姿态切换时工具/手/身体驱动不争用，恢复后无旧姿态残留；无效目标按项目规则处理。
- [ ] 分别记录手部、身体和视角通道的贡献，不将第一人称看不到的关节当已验证；若需要精确评估，另加调试视图。
- [ ] 刀刃可见接触与真实事件分别验收，原伤害、范围、频率与几何切断规则未被无意改变；不只为贴合演出移动目标或扩大判定。
- [ ] 头部 roll/垂直变化在实际第一人称下不妨碍瞄准和观察，测量舒适/可用性而非宣称作者已测；相机是否跟头应明确。

## 组合而不复制

- [方向瞄准与分件姿态](../gameplay-aim-pose/SKILL.md)处理 sprite/方向帧/stack 表示，本页是工具路径与持握/身体约束，不因都叫姿态共用实现。
- [动作响应相位](../gameplay-action-timing/SKILL.md)检查输入后冗余准备，本页不靠全段加速解决协调。
- [程序步态](../gameplay-gait-step-scheduling/SKILL.md)协调脚步状态与髋，不从膝弯文字接管工具动作。
- [装饰跟随](../gameplay-secondary-motion/SKILL.md)只处理次级滞后，双手持握不能简单当装饰追随。
- [几何事件对齐](../gameplay-geometric-event-alignment/SKILL.md)诊断真实切断边界，不由动画骨骼位置自动保证。
