# 完成事件、结算与动作尾声

## 触发条件

完成界面截断动作尾声，或结果计数、镜头、跳过互相打断导致重复结算。

## 输入与前置条件

权威完成/失败事件及结果 ID、结果快照、下一状态、镜头与输入归属、可跳过/中断方式。

## 实施步骤

1. 把业务完成和演出分开：收到一次确认结果后保存不可变快照，以结果 ID 防止重入触发再次结算。
2. 列出尾声期间继续运行的场景动作和允许输入；已完成的业务不因车辆仍驶离或动画未完变回进行中。
3. 需要终点视角时显式转移相机控制权，保留结果文字与离场主体。规定下一状态镜头归属，不把交接当临时 shake 的归零。
4. 把确认终值交给结果计数入口，显示中间值不发放得分；镜头与计数可以不同时间结束。
5. 正常完成、跳过、取消与退出共用幂等出口：停止本次显示任务、保留同一结果并移交正确输入/镜头。不必返回已经结束的追随模式。

## 参数调整

单独调镜头交接时长、结果出现时刻与尾声保持时间；若等待计数拖住出口，改为按项目规则立即展示终值，不重新结算。

## 验收与失败处理

- [ ] 正常、跳过、重复触发和重进只产生一次业务结果。
- [ ] 计数先完/镜头先完均可退出，没有输入锁或双相机控制。
- [ ] 关闭演出仍显示正确结果；对象级宝箱揭示不强套完整终点流程。
