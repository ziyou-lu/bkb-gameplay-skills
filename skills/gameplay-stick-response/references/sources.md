## 来源未提供

精确曲线类型、指数、控制点、径向或逐轴选择、符号与斜向处理、死区数字、外缘校准、滤波、最大速度及单位、引擎 API、消费者是否保留幅值均未知。不能假定所有硬件原始读数线性，不能把约 0.2 固化为半杆默认值，也不能用相邻俯仰限位帖子补出本帖的鼠标策略。

## 运行时必须由项目决定的契约

1. 归一化值究竟来自硬件适配器、框架死区后，还是某个已加工阶段；原始量程、中心漂移和外缘能否达到需在支持设备检查。
2. 径向方案保留方向，逐轴方案允许部分方向变化；哪种符合移动/观察意图由消费者决定。低死区是来源描述，不要求项目牺牲静置稳定。
3. 最大速率、轴增益、反转、设备仲裁和时间积分都沿用已确认接口。来源说的是曲线命令不随保持时长增长，不证明项目角色物理完全没有惯性或加速度。
4. 是否允许运行中改配置、何时提交，以及是否需要玩家菜单由项目决定，不因作者“考虑”设置选项就新建设置工作流。

## 本库提出的工程方案

正文中的单次处理管线、日志分层、有限值/曲线约束、非法配置回退、控制权清理、测试矩阵及相邻流程组合均为迁移设计，不是已检查的作者实现。

以下是可选径向候选，不是作者公式或通用参数：

- s 是已校准但尚未由本候选处理死区的二维输入；l = length(s)，r = min(l, 1)。l = 0 或 r <= d 时输出零。
- 由项目提供 0 <= d < 1。否则 q = (r - d) / (1 - d)，f(q) = q^gamma，gamma >= 1。gamma = 1 只作同死区线性基线，gamma > 1 在内部杆程压低幅值。
- 输出 (s / l) × f(q)。用真实长度 l 保留方向，用 r 控制幅值；不能用 r 归一化单位圆外的斜向向量。若上游已做死区与再铺满，本层 d 必须为 0。
- 1 是归一化端点，d/gamma 不提供默认值。候选不包含时间参数、记忆、速度单位、设备校准、鼠标、逐轴方案或引擎积分。其它单调曲线仍须自行验证插值内部区间。
- [radial_response.py](../scripts/radial_response.py) 是本库编写的纯函数参考，只验证上述选择；坏配置/样本抛异常以便测试，游戏接入层须按正文采取中性输出或已验证回退，不能把异常直接漏到帧循环。
- [对应单元测试](../../../tests/test_stick_response.py)验证零点、死区连续性、端点、单调、方向、四象限、单位圆外幅值、无历史及非法输入。测试值都是合成夹具，不是来源参数；通过不证明硬件、游戏手感、帧率、性能或可访问性。

## Owner 判断

新增 gameplay-stick-response / stick-response：每次有效模拟杆采样触发，输入为当前幅值及固定配置，输出为无历史命令；失败是中心漂移、跳变、过冲、幅值丢失或意外时间依赖。

- gamepad-pitch-limits 还需当前俯仰/合法边界，验收接近/离开端点，不拥有全杆程响应。
- pointer-curvature-steering 需位置历史和滤波状态；steering-assistance 需车辆行进状态及辅助合成，两者不等同静态曲线。
- movement-look-decoupling 决定移动与观察谁写方向，不决定杆量大小。
- 设置菜单只能消费项目已支持的配置，不能以作者正在考虑选项为证据合并到 contextual-ui。

上述四个已审定相邻路由与本入口登记双向 distinct_from；既有 owner 机制不搬迁。
