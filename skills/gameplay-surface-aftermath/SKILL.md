# 表面余效的贴地与边界适配

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 倾倒、碰撞等事件留下的水洼或其他表面余效悬空、穿出边缘，或无法顺应台阶高低。
- 固定平面/圆形水片不匹配窄槽或阻挡物，需要独立处理余效覆盖与承载地形的一致性。

## 先确认的输入

真实事件位置、允许承载的表面、必须截断的边界/阻挡物、视觉覆盖范围、生命期与生成频率，以及余效仅为视觉还是影响真实玩法。另确认项目可承担的采样/网格更新成本，不从来源推导通用预算或参数。

## 分步机制

1. 先检查承载面和边界，不只放大一个固定平面。固定事件位置与相机做对照，区分高度适配问题与横向穿边问题；明确哪些面允许承载、哪些障碍必须截断。这一决策顺序是本库迁移建议。
2. 以已见结果限定目标：DaIdIURzME9 的 Case 3 近侧视中，旧平面水片从阶梯向外悬空伸出，新水面顺应不同高度；Case 2 俯视中，旧圆水片伸出窄槽两侧，新水面沿槽内延展。两种视觉对照不能代替所有碰撞情形的验证。
3. 若需要候选生成管线，可参考作者正文描述的四步，而不是把它当成已核代码或必选算法：
   - 从中心以 BFS 生成扩散球。
   - 用横向射线检查墙，删除与 collider 相交的球。
   - 用向下射线寻找 floor，定位球的高度。
   - 用 Marching Cubes 转为游戏网格。
4. 按项目成本选择满足承载面/边界约束的表示与更新策略，不要求照搬上述算法。保持余效生命期、连续生成与清理受控；视觉网格贴地不等同新增碰撞、真实流体或玩法范围改变。
5. 将外观、更新成本和真实规则分别检查。若余效另有危险/可行走等玩法含义，显示应服从既定规则；若确实修改规则，另列规则验收，不能用“水面更贴地”代替物理正确性。

## 适用限制

- Case 1 未完整核验；Case 2/3 只支持已见的窄槽边界与阶梯高低视觉对照，不把三个 case 都记成已通过。
- BFS、横向/向下射线与 Marching Cubes 仅为作者文字描述，不是源码阅读、运行或性能实测；BFS 停止条件、采样间距/上限、射线配置、碰撞层和网格更新时间均未知，不补默认值。
- 不证明真实流体、体积守恒、任意地形稳定性或玩法碰撞随网格改变。该管线不是所有项目的通用最佳实现，音频未核听。
- 本技能处理接触事件之后的承载面适配，不接管接触闪光、冲击瞬间的粒子或通用伤害判定。

## 验收

- [ ] 在同一事件位置与相机下比较平地、台阶、边缘、窄槽和墙边，逐个确认目标承载面贴合与边界处理符合设计，不把来源的三 case 标签视为全部通过。
- [ ] 视觉覆盖不误导玩家对可行走/危险区域的判断；只改表现时不擅自改变碰撞和玩法范围，规则改动另有测试。
- [ ] 连续生成与清理时，实例数、采样/网格更新成本和残留状态受控；明确所选表示的适用场景，不由少数视觉结果推定复杂地形一律可用。

## 组合而不复制

只在需要相应机制时读取，保留表面余效独立的承载面与边界职责：

- [接触闪光、冲击帧与粒子](../gameplay-impact-visuals/SKILL.md)：处理事件发生瞬间的接触标记、爆发和尾迹；不在这里复制其命中反馈流程。
- [攻击预警与反制可读性](../gameplay-attack-readability/SKILL.md)：仅当表面余效承载真实危险区域时，复用表现与判定对齐的验收，不凭水面外形新增伤害规则。
