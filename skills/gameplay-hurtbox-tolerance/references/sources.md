# 小于视觉轮廓的受伤区域

来源展示 TINY HITBOX 的开关对照、较小中心区域和不同扣血结果；以下是迁移设计与验收建议，不是对引擎碰撞对象或作者源码的核验，也未在目标游戏中执行。

## 触发条件

- 弹体擦过可见角色边缘就造成伤害，项目明确要增加空间上的闪避余量。
- 改过角色缩放、朝向或动画后，受伤区域漂移；或缩小受伤区域时意外改变了走路、贴墙与落地碰撞。

## 先确认的输入

可见形象的轮廓、锚点与变换，实际接收攻击的 hurtbox 几何，攻击形状与命中规则，以及独立的世界移动碰撞体。选择目标受伤区域的宽高/半径/面积等明确单位，并确认动画、缩放和角色状态切换时是否改变区域。

## 分步机制

1. 同时显示可见形象、受伤区域和世界碰撞调试轮廓，复现中心命中与边缘擦过；先确认项目当前由哪个区域接收伤害，不能凭对象名称猜测。
2. 以明确的几何单位设计小于可见形象的受伤区域，保持可解释的锚点与位置。来源“38%”未说明计算口径，不直接代入宽、高、面积或统一缩放。
3. 让攻击接触候选通过受伤区域检查，再进入已有伤害流程；只有与该区域按项目规则相交才算命中。不要用“播放了受击效果”代替真实伤害判定，也不要额外加入减伤或无敌计时。
4. 将空间命中判定与世界移动碰撞分开。若当前共用形状，先分清各自用途再调整；移动阻挡、站立接触与导航占用保持既有规则，除非项目另有明确变更。
5. 检查缩放、翻转、动画和状态切换时区域随角色正确更新；用中心、边缘、快速与斜向攻击验证空间边界。对每种攻击形状单独测试，不能只凭一种弹道通过就推断近战或范围攻击也正确。

## 适用限制

- 作者标签为“player_hitbox = 38% // of the sprite you see”；38% 是示例且维度口径未知，不能重建精确几何或据此指定默认比例。
- 对照画面中 OFF 已降到 50 并出现 -25，ON 仍为 100，附近可见弹体；这支持不同受伤结果。碰撞过程为离散画面观察，未连续测量具体接触时刻或检查引擎对象。
- 来源没有证明世界碰撞体同步缩小，也未核验源码或音频。空间容差可能影响攻击可读性，不能把作者“Dodges feel fair”的目标当作已验证体验结果。

## 验收

- [ ] 受伤区域外的边缘擦过不造成伤害，中心相交仍能命中；边界算相交与否遵循已明确的项目规则。
- [ ] 缩放、翻转、动画和状态切换后，受伤区域与预定锚点一致，没有一帧漂移或遗留区域。
- [ ] 贴墙、落地和移动阻挡没有因调整 hurtbox 意外改变；调试显示能分清两类区域。
- [ ] 各攻击形状、速度及方向分别验证，不漏检中心命中，也不在区域外凭视觉效果扣血；关闭调试后检验视觉与玩法的可理解性。

## 组合而不复制

- [受击后的短时保护](../../gameplay-post-hit-protection/SKILL.md)处理已接受命中之后的时间窗口，不替代空间相交检查。
- [低血量伤害缩放](../../gameplay-low-health-damage-reduction/SKILL.md)处理符合条件时的伤害量，不缩小受伤区域。联用时分别记录未命中、被免疫和实际减伤的原因。
