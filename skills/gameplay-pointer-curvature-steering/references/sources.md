# 鼠标轨迹曲率到转向输入

来源提供实机示范与作者解释的两级平滑管线，没有旧新输入回放或源码。以下是迁移设计与验收流程，不是已验证的滤波器/曲率公式，也未在目标游戏中运行。

## 触发条件

- 项目明确采用鼠标画圈/弯曲轨迹控制车辆转向，需要解释或调整连续输入的稳定性与响应取舍。
- 已有轨迹转向在直线、停止或快速反向时产生异常输出，需要分清采样、滤波和转向映射的问题。
- 若要在已有驾驶输入上叠加行进方向辅助，使用[车辆转向辅助](../../gameplay-steering-assistance/SKILL.md)；仅想让车轮外观跟随真实转向不需要引入本流程。

## 先确认的输入

带时间戳的鼠标位置、坐标空间与灵敏度、当前滤波级数/参数、历史记录的采样来源、曲率定义及正负方向、转向范围与输出更新时钟。明确项目已经选择轨迹曲率控制，不擅自把直接指针瞄准或左右按键替换为画圈操作。

## 分步机制

1. 同时记录原始位置流、各平滑阶段路径和最终转向量，先定位异常发生在哪一层。调试颜色须有明确图例；源帖的青→洋红→白对应来自作者回复，不是可由颜色反推的算法。
2. 以作者的“位置先平滑两次”作为一个候选管线，分别检查第一、第二阶段的影响。滤波函数与系数未公开，按项目选型与验证，不把多一遍平滑自动当作改进，也不补写成某种已知 lerp 或低通实现。
3. 明确从哪个阶段读取历史位置，并按时间戳取所需样本；处理历史不足与采样率变化。作者称取过去 50 和 100 ms 的位置估计曲率，这些是回看间隔，不是总延迟、缓存窗口或独立测得的最佳值。
4. 定义曲率正负与转向方向的映射，并单列近零移动、共线样本、停止和反向的输出策略；限制输出范围。具体曲率公式、插值、死区、饱和与灵敏度是项目决策，来源没有验证这些实现。
5. 用同一份记录轨迹对照无平滑、单级与两级候选，比较直线噪声、保留方向、反向响应和停止残留。改变滤波时先固定车辆碰撞、牵引与镜头，避免把其他改动归为输入改进。
6. 初始化、输入设备/坐标变化、失焦、暂停或控制权切换后，按项目规则清空/重建历史及滤波状态；恢复时不能把旧位置跳变解释成一次急转弯。

## 适用限制

- DZybNWexMRB 可见车辆、车轮转角、转向表与彩色路径，后段在家具周围驾驶。支持游戏内演示，不证明固定输入对照、量化噪声下降或更快成绩。
- 两次位置平滑及 50/100 ms 历史曲率来自已展开的作者回复；没有源码、滤波系数、曲率公式、样本插值或实际输入到转向延迟测量。不能把两个间隔相加成 150 ms 延迟，也不能宣称零延迟/帧率无关。
- 不推断世界碰撞、摩擦或轮胎牵引改变；音频未核听。此流程不是轨迹手势识别器、自动驾驶或一般鼠标瞄准教程。

## 验收

- [ ] 相同记录输入下，直线、顺/逆时针、停止再开始与急反向各有可解释输出；方向符号不因滤波或坐标变换反转。
- [ ] 对比单级/两级时同时记录稳定性和响应，不用历史间隔代替端到端测量；接受的延迟/残留由项目明确。
- [ ] 不同帧率/采样率、历史不足、近零移动及共线样本均有明确处理，不出现无效值、瞬时满舵或无限保留旧转向。
- [ ] 失焦、暂停、坐标/设备变化及控制权切换后历史恢复正确；可视路径、转向量与车辆实际响应能逐层对照。

## 组合而不复制

- [车辆转向辅助](../../gameplay-steering-assistance/SKILL.md)处理车辆状态相关的辅助量，不负责从鼠标路径推导玩家命令；联用时分别记录两者贡献。
- [移动接触表示](../../gameplay-locomotion-contacts/SKILL.md)只在轮胎接触覆盖问题时启用，不用换碰撞形状掩盖输入滤波问题。
