## 支持的机制与未知项

支持的机制：房间级选择状态、选中房间焦点、相对该焦点的环绕/缩放、房间之间平滑聚焦。所谓房间锁定是观察焦点锚定，不能据此要求相机物理位置始终位于房间内。

未给出：选择按键映射、邻接/目标搜索规则、焦点计算方法、插值曲线与时长、缩放及俯仰边界、墙面剖切算法、过渡打断行为、朝向是否保留。白色玩家图标不是房间选择解析算法的证据。不能把跨高度选择推断为任何具体图搜索、射线选取或楼层切换实现。

## 本技能补充的工程方案

以下为迁移实施与待验证验收设计，不是作者已展示或已测试的内部实现：

- 将房间注册表、选择解析器、焦点/取景数据作为项目输入，缺少方向解析时只接有效 ID 的直接选择。
- Closed/Focused/Transitioning 状态、会话与过渡标识、最新有效目标重定向、幂等同房间选择、失效房间回退及退出控制权清理。
- 从焦点与环绕/缩放参数重建视图；透视距离向量与正交尺寸的候选实现，俯仰限制、偏航归一化、房间级取景范围和地图时钟。
- 过渡期间允许重新选房而暂缓查看输入，是正文提供的可选工程起点；同时查看需要统一写入者。曲线、时长、输入阈值与朝向策略均待项目选择。
- 上下堆叠房间、不同大小、快速重选、退出/重开、暂停、对象失效和减少运动等验收用例。尚未运行引擎实现或玩家测试。

## Owner 边界与登记

- gameplay-room-map-navigation：持续地图模式中的房间选择/焦点、相对观察及房间切换生命周期。
- gameplay-camera-feedback：事件触发的临时 shake/impulse/punch-in，不拥有持续地图导航。
- gameplay-completion-sequences：权威完成事件后的结算/尾声与镜头交接，不负责任意房间查阅。

### 项目运行选择

地图呈现与真实世界必须明确分离；可浏览资格、基础可见性、代理归属和其它筛选由项目提供。隔离选择何时变化、加载中显示方式、模式是否记忆、全局标记/列表是否保留均需明确政策。正文采用“逻辑选房时立即切过滤、相机继续过渡、打开默认 Normal”作为可实施起点，不冒充来源行为。

### 本库新增的工程设计与检查

- Normal/Isolated 与相机过渡正交，共用 selectedRoomId；幂等设置模式和按下沿 Toggle。
- 本会话独有的地图过滤贡献与最新基础可见集合求交，不快照覆盖整张可见性表。撤销只移除本层贡献，保留实时变化的探索/楼层/其它过滤；不操作世界房间、流送、碰撞或共享全局渲染资源。
- 渲染可见集合与导航候选集合分离；房间几何/注释/拾取与允许信息同步，秘密聚合状态不受筛选改变。
- 同一逻辑选择提交、异步结果的会话/选择代次、目标失效回退、基础显示筛选改变后的冲突政策重判、新代理首帧过滤、所有权清理和失败验收均是工程补充，不是作者已公开或测试的内部状态机。
- [isolation_policy.py](../scripts/isolation_policy.py) 仅给出纯集合交集候选；[单元测试](../../../tests/test_room_map_isolation.py)检查实时基础集合、切换、失效与输入不被修改。它没有渲染器、输入事件、会话句柄或异步加载实现，不证明游戏生命周期测试通过。

### 为什么补原 owner

隔离是当前房间浏览模式的可见性控制：触发为对当前选择切换显示模式，输入复用同一 roomId、可浏览/呈现资格，状态依附同一会话及选择，失败验收涉及选中一致性、换房、关闭恢复和不污染世界。相机聚焦与显示过滤仍是两个独立控制/机制，但两者共用房间浏览状态和出口，由 gameplay-room-map-navigation 唯一持有；不复制选择状态、另造按帖子命名的技能或把过滤改称相机算法。

新机制 selected-room-map-isolation 与原 room-map-navigation 并列归该 owner，同一路由增加明确隔离请求示例。paused-map-backdrop 仍只管理捕获背景；room-secret-markers 仍只管理权威秘密存在性；contextual-ui 仍只管理按钮焦点/提交反馈，均不拥有这份房间过滤状态。
