# 合法起跳事件的水平动量修正

## 效果预览

相同右向助跑与向左合法起跳；右采用明确替换分支重新定向，左右相同竖直曲线和落地时刻。

左侧为使用前，右侧为使用后；4 秒循环，用途示意（非引擎实测）。

![合法起跳时，再决定水平走向：使用前后对比](assets/before-after.webp)

## 触发与范围

只有项目明确希望改变实际移动时使用：玩家按方向起跳后仍被旧水平惯性带走，希望在该次起跳时重新定向，或为地面静止起跳增加方向推进而保留一部分助跑速度。它会改变落点与关卡可达性，不只是动画变快。

本入口在已有跳跃成功接受点修改一次横向速度，不授予空中跳、不保留输入命令、不延长离地许可，不持续提高空中控制响应。先与原控制比较，确认惯性是需要改变的规则，而非本应保留的动作承诺。

## 输入与前置条件

- 控制器唯一的起跳接受/提交点、跳跃实例 ID、控制器生命代次与动作类型；拒绝事件不得进入修正。明确地面跳、离地宽限跳、空中跳、墙跳和外力发射各归哪个策略，默认不把特殊动作自动纳入。
- 当前权威速度、速度写入归属、物理更新顺序和碰撞求解。确认速度是世界值还是已相对平台的值，哪些分量属于玩家移动，哪些是平台继承、击退或其他外部效果。
- 项目定义的横向轴/平面、上方向、期望移动方向与死区；明确缓冲输入在真正起跳时读取当前方向，还是使用已保存的方向快照。不能从角色朝向或镜头观察方向猜玩家意图。
- 当前状态的最大漂移速度、可用修正策略和速度上限，均使用项目速度单位。先选择地面与空中策略、无方向规则、摇杆幅度规则、外力/超速处理及碰撞优先级，不从动画填参数。

缺少接受事件或速度归属时先定位控制器接口；没有可靠的分量拆分就暂停对外力/平台的扩展，不在 UI 按下或动画事件里另写整段速度。

## 实施步骤

1. 保存严格基线，记录按键意图、起跳接受时刻/类型、横向速度前后值、垂直速度和落点。复现站立、同向助跑、反向助跑、空中跳、无方向和被击退场景。把一次跳跃事件的修正与地面加速度、持续空中漂移控制分开开关。
2. 在唯一跳跃提交过程中按跳跃实例和控制器代次锁存本次处理。若跳跃因资格不足被拒绝，或只是缓冲了命令，不改变水平速度；命令以后获准起跳时才处理一次。持续按住、重复事件、动画重播和重复网络通知不能再次施加。同一物理步内多种许可同时满足时仍只消费控制器接受的那次起跳；项目真正允许的新空中跳有新实例，不能因旧锁存被误拦。
3. 从该次接受上下文确定策略类型及有效期望方向。离地宽限获准时可能已不接地，按项目对该起跳的分类选策略，不在写完垂直速度后重新看瞬时 grounded 猜类型。将期望输入映射到项目横向轴/平面并处理退化/死区；无有效方向时沿用声明的保速或不修正策略，不任意选世界轴。若按满漂移速度重新定向，将方向归一化；若采用摇杆幅度缩放，则将其作为明确的玩法变体，不把两种规则混用。
4. 提取获准修改的横向玩家速度 `v_h`，读取当前有效漂移速度 `V`，令已选方向速度 `c = direction * V`。选择一条分支，不叠用：
   - 替换：`candidate = c`，明确丢弃该可控横向分量的旧惯性；适合项目允许立即重新定向的跳跃类型。
   - 增加：`candidate = v_h + c`，保留原分量后叠加方向速度；可用于项目选择的地面起跳。它不是“永不反向”的保证：较小同向旧速度加较大反向修正仍可翻转，必须用实际速度区间验收。
   这两种是速度赋值/增量，不是加速度，不乘物理步长，也不同时通过刚体冲量和控制器速度施加两遍。缺失、非有限或非法的速度配置不执行修正，报告配置错误并沿原跳跃路径继续。
5. 对候选执行已声明的限速/保速政策。明确地面增加能否超出普通漂移上限、允许的跳跃上限，以及已有超速如何处理；增加分支不能靠连跳无界叠加。若设计要求保留外力或平台继承，修正仅作用于已分离的玩家分量，再按控制器原规则合成这些贡献一次。已经相对平台的速度不得再减平台速度；不能以总速度封顶无意消除获准保留的击退。若“保留超速”和“所有总速强制封顶”等要求冲突，先确定优先级，不宣称同时满足。
6. 在原运动更新中合成最终速度一次，保留本次跳跃已决定的垂直分量和其他未授权分量。写清跳跃竖向赋值、横向事件修正、持续加速度/阻力及碰撞求解的先后，避免地面移动分支在同一步覆盖修正，或把旧整向量写回覆盖新的起跳速度。接下来的普通空中控制按原规则运行；碰撞仍可阻挡/改变速度，本机制不绕过墙体或承诺指定落点。
7. 死亡、传送、重生和控制器替换时使旧事件代次失效。中断后的恢复从当前速度和当前动作读状态，不重新播放旧修正或把起跳前速度恢复回来。调试记录本次事件是否处理、策略、方向、修改分量与限速原因，方便区分资格、输入采样、重复写入和碰撞阻挡。

## 调参顺序

先确认接受事件只作用一次、速度空间与分量正确，再在项目真实速度范围比较替换和增加，随后确定上限/超速及外力政策，最后调方向死区或幅度规则。先固定跳高、重力和持续空中加速度，避免多个改动互相掩盖。

同向增加可能把速度推高，反向增加的效果取决于旧速度大小；不能只在“旧速恰等于修正量”的单一场景证明不会瞬间反向。逐步加入速度增益、平台和外力后再复测关卡可达性，不把更迅速自动视为更好。

## 可观察验收

以下以 `V > 0` 和一维左右方向为逻辑夹具，不是推荐项目数值；关闭其他加速度并在事件提交后、碰撞前取样，再另测完整物理步。

- [ ] 替换分支在有效向左输入时得到玩家横向 `-V`，不论原玩家横向为正或负；实际垂直起跳值、跳次数和其他保留分量不变。
- [ ] 增加分支：静止向右得到 `+V`；原 `+V` 加向左 `-V` 得到 0；原 `+0.25V` 加向左得到 `-0.75V`。行为符合已选方向政策，不能把后一例错误宣称成不会反转。
- [ ] 原 `+V` 同向增加的原始候选为 `+2V`，最终结果严格符合项目上限策略；重复合法跳跃仍有界，拒绝的连按完全不修正。
- [ ] 长按、重复同一事件/通知、缓冲未获准和已失效命令都不增加第二次修正；缓冲真正获准、离地宽限与新合法空中跳按各自类型恰好处理一次。
- [ ] 方向为零、死区边缘、轻推摇杆、反向、方向在缓冲期间改变以及非世界 Y 上方向，均符合输入快照和横向空间契约，不注入垂直速度。
- [ ] 已超速、击退、移动平台、速度增益及墙跳/发射等特殊类型分别遵守声明范围；不二次继承平台、不悄悄消除外力、不自动开启未支持的跳跃。
- [ ] 同一物理步内起跳后修正不会被地面更新清零；撞墙/低顶仍按求解器处理。跨渲染帧率和支持的物理步长复测事件后速度及落点，不用动画帧证明正确。
- [ ] 暂停恢复、死亡/传送后迟到事件和控制器复用不重放旧速度修改；比较相同路线的落点与可达区域，报告实际规则变化。

## 失败恢复与组合

空中无效按跳也转向时，先查是否绑定在原始输入；越连跳越快时查同实例重复处理和增加分支上限；起跳失去高度时查整向量旧值回写；平台/击退异常时查分量归属和参照系，不靠更大修正量掩盖。

[输入缓冲](../gameplay-jump-input-buffer/SKILL.md)保留早按命令，[离地宽限](../gameplay-jump-forgiveness/SKILL.md)决定晚按许可；本项只消费其已接受的起跳。[按住高度](../gameplay-variable-jump-height/SKILL.md)与[升降重力](../gameplay-asymmetric-jump-gravity/SKILL.md)处理竖向轨迹。[下冲滚动动量](../gameplay-dash-roll-momentum/SKILL.md)另有落地转换与可消费预算，不复用成普通起跳增速。

需要核查机制出处、作者建议与工程边界时读取[来源参考](references/sources.md)。

与[腾空招式对齐](../gameplay-airtime-trick-alignment/SKILL.md)组合时，将实际提交后的运动状态提供给预测器；本项改的是速度，后者只安排兼容条件下的表现时间。
