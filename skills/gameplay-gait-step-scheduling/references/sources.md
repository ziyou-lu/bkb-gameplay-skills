# 程序步态的预测迈步与髋部协调

本流程针对已有程序化步态的脚步与髋部协调，不从姿态截图反推出精确时序。来源的先脚后髋与转向选腿来自作者说明；下面的工程步骤和验收不是已运行的 IK 实现。

## 触发条件

- 站立后启动时，身体先移走、脚等距离拉开才追赶，看起来像向前跌倒。
- 转向时已有步态不能及时选择支撑/迈步脚，想补启动与转身的预测步，而不是仅增加朝向动画帧。
- 持续行走时，每只脚独立驱动同一个髋运动通道，输出相互抵消或叠加冲突。

## 先确认的输入

移动启动/停止意图、期望行走方向、髋部转向意图、当前脚位与落脚状态、已有步态调度和角色根运动规则。明确局部/世界方向及顺逆时针约定；步长、轨迹、持续时间、选腿仲裁、落点合法性和 IK 解算由项目提供。髋部冲突分支另需每脚运动状态、同时前进条件、各路髋偏移与最终共享输出。

## 分步机制

按问题选预测迈步或共享髋通道分支，两者可共用脚步状态，但不是同一触发规则，也不要求顺序叠加。

### 启动/转向预测步

1. 对照站立启动与左右转向，显示根/髋、双脚及现有迈步触发。区分“身体位移后才追赶”的启动调度问题与脚底接触或 IK 本身错误。
2. 在启动意图产生时安排朝该方向的预测步，不只等待根与脚拉开距离。DZ0HGqjvGkz 作者说明先向启动方向迈步，再移动髋；精确先行帧数和身体运动方案未给出，项目需协调视觉时序与权威移动，不能为演出擅加输入迟滞或改速度。
3. 转向时按约定选择迈步侧。作者例子为髋顺时针转动用右腿、反向用另一腿；先核坐标、身体朝向及当前支撑脚，不把这个左右映射当跨视角通用公式。
4. 把预测步接入已有步态状态，而非另起一套竞争调度。启动、转向与持续行走触发同时出现时，按项目规则仲裁；一只脚正在迈步时怎样排队、取消或改目标必须明确。来源未给这些策略，不能声称已解决双脚同时离地。
5. 复核停止/重启与快速反向，再按项目运动范围检查坡阶和姿态切换。比较身体前倾观感、脚底滑移和支撑顺序，保留原有可用的持续步态，不因新增预测步就重写全部移动控制。

### 持续步态的共享髋通道

1. 记录每脚事件驱动的髋偏移及最终合成结果，区分脚步没有触发、贡献相互抵消和叠加过大；不要只单独加大每腿幅度。
2. DZXG7dZS_zz 作者称原每脚独立 hip bob 在行走时互相抵消，新版另外检查双脚同时向前走并分别处理该条件。本分支可据此评估“并发脚状态→共享髋输出”的项目策略，但具体条件、相位和合成公式没有公开。
3. 与启动/停止、转向和当前落脚状态一同检查，明确最终髋通道的输出权，避免多个驱动争用。共享振荡器、优先级或归一化均不能写成来源已实现的方案；预测步不自动解决髋偏移抵消，此分支也不自动保证支撑平衡。

## 来源与适用限制

- 实见 Before/After 上下骨架对照、脚腿位置不同及 feet BEFORE hips / rebalances 字样；启动因果顺序与转向选腿规则来自作者正文/解释，不是我们逐帧测出的结果。
- 作者说原步态已含 overshoot，但仍在启动时像跌倒；这不证明新增了 overshoot，也不应把此任务归为装饰回弹。作者认为改善微妙且更好，不等于偏好测试或物理平衡证明。
- 没有源码、IK 求解器、步长/高度、触发阈值、先行帧数、仲裁/落点约束、性能或零滑步保证；未核听音频。A/B 未核同步相同输入。
- DZXG7dZS_zz 的蓝色场景 Before/After 较暗，只能确认标注与不同姿态；每脚驱动互消及双脚同前进另处理来自作者说明，不能从截图独立量出髋幅度/相位或显著收益。未给条件、合成函数、共享振荡器、参数或代码，不把它当预测步来源的实现证明。
- 本页不负责输入命令缓存、AI 路径决策、移动碰撞或完整生物力学；脚接触正确、状态不冲突和根运动不意外改变均需目标项目验收。

## 验收

- [ ] 同路线/指令回放多方向启动、左右转身，记录脚与髋的事件顺序；预测步能解释启动意图，不仅比较不同姿态截图。
- [ ] 确认坐标与选腿规则，检查原地转向、平移加转向、快速反向、微小指令和速度变化；不会因重复启动让调度互相覆盖。
- [ ] 检查支撑脚、同时触发、停下重启、已有步未完成和姿态切换，无项目不可接受的双脚冲突、交叉或脚底滑移；不把来源当作这些测试已通过。
- [ ] 坡面/阶梯按项目落点与 IK 能力分别验收，不能把视觉“重心调整”当真实稳定性证明；明确失败回退。
- [ ] 原移动速度、输入响应、碰撞与持续步态未被无意改变；若需要修改真实移动规则，应另作玩法决定与对照测试。
- [ ] 共享髋通道记录每脚与最终输出，覆盖单脚、交替、双脚同时前进、原地转身、起停与反向，无不期望抵消、双倍幅度或跳变；这项项目验收不能替代原帖未测的改善量。

## 组合而不复制

- [移动方向动画](../../gameplay-movement-feedback/SKILL.md)选择方向姿态，不调度哪只脚何时迈步。
- [装饰跟随](../../gameplay-secondary-motion/SKILL.md)管理次级滞后，不决定支撑顺序。
- [动作响应相位](../../gameplay-action-timing/SKILL.md)检查输入后准备段，不提供本页的步态调度。
- [移动接触表示](../../gameplay-locomotion-contacts/SKILL.md)处理接触覆盖，不因名字含 locomotion 就拥有脚步时序。
