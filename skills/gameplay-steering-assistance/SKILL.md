# 车辆转向辅助与直接控制

## 触发条件

- 手柄/键盘直接转向难以细控，简单放慢输入却损害响应。
- 已有辅助压过玩家意图，或关闭后不能恢复直接输入。

## 输入与前置条件

原始输入、车辆行进方向/速度、当前转向映射与物理更新时钟、输入设备、辅助开关和项目控制目标。轮胎接触形状与悬架规则保持独立，不在辅助实验中同时改动。

## 实施步骤

1. 固定车辆、路线、入口速度与设备，记录直接输入和整体平滑输入两套基线，区分突兀与迟滞。
2. 取得玩家原始转向命令及车辆有效行进方向，定义允许辅助的速度/状态；低速方向不可靠时采用明确禁用或减弱策略。
3. 将趋向行进方向的辅助作为单独通道，与玩家输入合成前限制范围。明确混合权重、优先级和最大辅助，不让辅助变自动驾驶。
4. 保留可关闭开关，关闭时清空辅助历史并恢复原直接映射。漂移、反向和状态重置分别检查，不用整体平滑隐藏混合错误。
5. 录制输入到转向响应和轨迹，键盘/手柄分开对照；测试期间固定摩擦、悬架与碰撞，只评估输入映射的变化。

## 调参顺序

先将辅助权重从零小幅提高，再检查高速/低速与漂移分段；分别调辅助上限和状态切换，避免增大平滑时长掩盖玩家反向意图。以响应与轨迹误差记录取舍。

## 失败处理

辅助抢方向时降低权重或收紧允许状态；低速乱摆查方向有效性；关闭仍有偏置查残留量；暂停恢复跳变查时钟和历史清理，不能宣称辅助天然零延迟。

## 验收

- [ ] 同条件对照直接输入、输入减速与辅助，分别记录输入到转向响应和行驶轨迹。
- [ ] 不同速度、漂移、快速反向与低速方向不稳定时，辅助不会压过项目保留的玩家意图。
- [ ] 反复开关、暂停/恢复及车辆状态重置后，关闭辅助仍恢复原直接控制，不残留辅助量。
- [ ] 键盘与手柄分别检查；比较时不混改碰撞、摩擦或悬架，不把其他系统收益归给辅助。

## 组合与边界

- [鼠标轨迹曲率转向](../gameplay-pointer-curvature-steering/SKILL.md)：从鼠标位置历史推导玩家命令，与本页利用车辆行进状态叠加辅助不同；不能只因都称转向而共用流程。

- [移动接触表示](../gameplay-locomotion-contacts/SKILL.md)：只有接触覆盖不够时才修改采样/形状。
- [速度镜头](../gameplay-speed-camera/SKILL.md)：持续速度表现，不代替控制映射。
