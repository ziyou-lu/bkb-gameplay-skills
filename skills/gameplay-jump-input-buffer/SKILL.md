# 落地前跳跃输入缓冲

本文件提供从公开视频和开发者文字提炼的设计与验收流程。未读取新演示的引擎源码或执行目标游戏；下面的状态组织与测试是实施建议，不是原作者已验证的代码。

## 触发条件

- 玩家在即将落地时按了一次跳跃，但因当时尚未接地，落地后没有起跳。
- 已有缓冲导致过期输入、长按或同一命令重复触发，需要检查输入生命周期。
- 若按键发生在离台之后，转到[离地宽限](../gameplay-jump-forgiveness/SKILL.md)；若是撞头角落，转到[顶角修正](../gameplay-ceiling-corner-correction/SKILL.md)。

## 先确认的输入

输入按下事件与保持状态、项目允许起跳的条件、输入采样与物理更新顺序、所用时钟、现有空中跳/自动连跳及死亡、暂停、传送状态。先明确项目要保留一次按下，还是要求到落地时仍按住；两者不能从不同来源拼成同一个已知规则。

## 分步机制

1. 复现落地前过早、略早与落地后的按键，记录输入和接地变化，不用演示里的图形区域代替真实时序记录。
2. 在约定的按下事件到达时保存有限期的待执行跳跃意图。时间窗、后续按下是否替换旧命令和松开是否取消，由项目定义；不直接套用 coyote time 的参数。
3. 在真实可起跳条件满足时检查未过期的意图，再执行跳跃。缓冲只保存命令，不应自行创造接地、空中跳次数或控制权限。
4. 以一次成功执行为消费边界；过期及项目指定的中断状态清除意图。明确同一更新中落地、过期与输入的先后，防止只在特定帧率偶尔丢跳或重复跳。
5. 与离地宽限组合时分别管理“命令仍有效”和“动作可执行”两件事，只在都满足时执行一次。各自开关及一起开启都要测试，不以组合成功证明每个机制独立正确。

## 来源差异与适用限制

- Dd1oVudtQj8 的 INPUT BUFFER 段可见 OFF 角色留在平台、ON 角色再次腾空，并显示早按被忽略/保存。0.12 秒、120 ms 是作者展示值，不是实测最佳值；SAME INPUTS 未经输入日志验证。图形区域不证明空间检测器，代码样标签不是已读源码。
- DeaF1wMgtg1 关联的第一方文章 [Celeste & Forgiveness](https://www.mattmakesgames.com/articles/celeste_and_forgiveness/index.html) 第 2 节描述落地前短时间按下并保持跳跃，在落地当帧起跳；没有缓冲数值。该旧视频未核输入缓冲 A/B，固定 Player.cs 仅见消费调用，仍未核其缓冲实现/时长。
- 新演示补足一种早按接受对照，不反向证明 Celeste 使用 0.12 秒，也不解决按住/松开语义、帧序和重置策略的缺口。不将此流程泛化为所有动作或联网输入队列。

## 验收

- [ ] 同一路线在落地前窗口内单按：开启时在合法时机跳，关闭时不因该旧按键跳；过期按键不能执行。
- [ ] 一个命令最多执行一次；保持、松开、重复按及再次落地符合事先声明的输入规则。
- [ ] 接近过期边界、不同帧率/更新顺序和项目支持的暂停后，行为与选定时钟一致。
- [ ] 死亡、传送和控制权切换不留下意外待执行输入；与 coyote/空中跳组合不增加未授权跳跃次数。

## 组合而不复制

- [离地跳跃宽限](../gameplay-jump-forgiveness/SKILL.md)管理离台后许可，不拥有待执行命令。
- [落地反馈](../gameplay-landing-feedback/SKILL.md)只表现实际落地事件，不以落地动画结束判定可跳。
