# 游戏内交互状态与提交反馈

## 触发条件

按钮、按住操作或指令焦点看似成功，却不符合真实交互结果；或菜单入场热闹但当前选择与其他选项难以区分。

## 输入与前置条件

可用、聚焦、按下、执行中、成功/失败事件；输入映射；目标/焦点归属；保持、释放及取消条件。

## 实施步骤

1. 建立状态到显示的映射，聚焦、按下和提交成功分别表示；显示订阅业务状态，不让动画结束调用一次额外提交。
2. 按钮按下可压缩、回弹和扩散波纹；成功提示仅由确认结果触发，失败/不可用采用可辨认的不同显示。
3. 按住操作绑定真实保持进度，松开或取消按规则清空/保留；满进度仍需确认结果，切换焦点不得把旧进度提交给新对象。
4. 拾取提示沿项目距离/朝向和输入映射显示；成功后同步持有状态及世界对象，等待确认时避免重复请求。
5. 战斗指令用焦点滑动、放大与说明框表达唯一选择和可执行性；卡牌布局、对话与机关执行交给独立入口。

## 菜单焦点对比与错峰入场

1. 先保留稳定的逻辑选项顺序、唯一焦点、可用状态和提交接口。将视觉变换放到独立容器上，不让缩放/倾斜反过来修改选中项或触发选择；焦点移动和真正执行是两个事件。
2. 同时定义选中与未选中样式：选中项相对基准放大，并反转底板/文字的明暗关系；其他项适度缩小或变暗，仍保留标签可读性。不可用项另有标记，不能只靠同一种变暗把“未选中”误作“不可执行”。焦点指示箭头可提供额外形状线索，不只用颜色。
3. 若采用斜切底板和级联排列，按选项索引计算布局锚点，再让各项动效绕自身锚点播放。布局位移与动画位移分开；不同分辨率、长文本和本地化下重新检查裁剪、间距与文字阅读，不盲抄固定坐标。倾斜装饰不要求文字也倾斜。
4. 开菜单时按稳定顺序错峰播放各项进入，可用有轻微过冲的回弹缓动。错峰只控制显示时间；若未出现的项不可交互，就同步门控输入，或采用立即完整可交互的低运动方案，避免玩家选到看不见的目标。关闭/重开取消旧序列，不累计重复弹入。
5. 快速导航时从当前视觉值过渡到最新焦点目标；撤销旧动画的完成回调，不叠加多次缩放。每次先恢复旧焦点的普通样式，再更新新焦点，使所有项最终收敛到一组状态。鼠标命中区域要与实际呈现策略一致：若用固定逻辑热区，避免明显偏离可见选项；若变换热区，保持导航顺序和最小可用面积。
6. 确认反馈可加轻小整板缩放脉冲；闪光与大幅移动均应有关闭/减弱路径，不能成为唯一成功信号。对异步操作，点击只表示已请求，成功仍待真实结果。面板遮挡切换复用[切场遮蔽与就绪恢复](../gameplay-scene-transitions/SKILL.md)，不在动画时间点私自重复提交或假设页面已就绪。

调参先比较选中/未选中的相对尺度和明暗，再调过冲与错峰间隔，最后加入整板脉冲。对照静止、慢导航、连续快速导航、关闭重开与减少运动模式：焦点唯一、文字清楚、无旧项残留放大、隐藏项不会误触且业务动作只提交一次。降低动效后也必须能看出当前选项和不可用项。

## 参数调整

按下位移、回弹幅度与波纹寿命先小后大；保持时长属于输入规则，不能仅为动画好看改变。优先修焦点/状态错误，再调动效。

## 验收与失败处理

- [ ] 鼠标、键盘及适用手柄焦点唯一，按下/松开/取消不误提交。
- [ ] 重复点击、关闭重开与拾取竞态不双发结果；条件不足不播成功。
- [ ] 减少运动后仍读得懂结果，旧目标消失时焦点与待完成显示被撤销。
