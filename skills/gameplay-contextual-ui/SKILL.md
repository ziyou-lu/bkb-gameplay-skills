# 游戏内交互、卡牌与对话

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 看不出可交互、悬停、选中与提交成功的区别，或设计上应能发现的目标混入水体/背景而难辨。
- 卡牌、菜单或对话动画隐藏真实焦点/进度，或世界内目标圈与目标深度/位置错位。
- 压板、开关与门体动作缺少清楚因果，或有机械运动但缺少与环境接触的反馈。
- 玩家角色被前景建筑/环境遮住，位置或轮廓难辨，需要比较局部透视与角色轮廓提示。
- 卧室、走廊等场景切换中出现突兀显示或出生位置瞬时跳变，需要视觉过渡，但仍应单独修复切场正确性。

## 先确认的输入

当前交互状态、真实提交/拾取结果、输入设备、焦点对象、世界/UI 层级与动效偏好；机关另确认压板/开关状态、开关门方向、门碰撞与实际可通行条件。临时识别模式另明确进入/退出状态、允许高亮的目标集合和既有距离/遮挡规则；遮挡角色分支另区分应保持可见的角色与不应被泄露的场景信息。切场分支另确认目标场景、出生点/相机设置完成条件、加载失败处理与输入恢复约定。

## 分步机制

按交互类型选取对应分支，不要求把所有动效叠在同一对象上。

1. 先列可用、聚焦、按下、选中、成功/失败状态；表现绑定实际状态而不是单纯鼠标经过。
2. 实体按钮以 press down、overshoot、ripple 和成功 reward 分层；按下反馈不等于执行成功。
3. 机关反馈先表达“触发器状态→机械位移→环境接触”。DeY6lNdTxTe 可见踩压板门下降、离开后升起，再加入门底尘团和镜头位移，最后使用纹饰分栏门并呈现各栏错落下降。迁移时先对齐触发和运动方向，接地粒子复用共享接触特效，镜头复用共享相机反馈；是否分段变化依材质/机关设计决定，不假定随机错峰算法。通行与碰撞按真实规则更新，不能仅凭动画看似打开就视为可穿过。
4. 拾取物根据已有距离/朝向条件显示提示，成功后更新世界物体与持有状态；F 是原帖示例按键，实际按键应取项目映射。
5. 当目标本应可发现时，先在实际相机下检查屏幕尺寸、出现位置与背景对比，再考虑涟漪等环境提示；水下捕猎例中放大鱼、让鱼更近岸是已见对照。视觉放大与碰撞体/生成位置改变要分开，后者可能影响可达性和难度，需按项目规则明确验证。这个优先顺序是迁移提炼，不意味着所有隐蔽/狩猎设计都要消除发现难度。另一分支是临时识别显示：DPjC2p_jDK- 的 Bird Vision 把场景压为蓝暗色、枝条显示青绿轮廓，之后恢复普通色。若项目需要这种模式，分开维护显示状态与真实交互/拾取状态，只突出设计允许发现的目标，退出后恢复原显示；不要顺带扩大检测范围、穿墙显示或自动收集。它与改目标大小/位置是不同方案，不必叠加。
6. 角色被遮挡时，按任务比较局部透视窗口和角色轮廓，而非默认两者叠加。Dd7GYLGPlon 对照圆形可见区域与白色猫轮廓，作者尚未给出赢家；点阵透明只是可见表现，不代表已核算法。这一分支旨在辨认被遮挡角色，不等同 Bird Vision 的资源识别模式。迁移时在相同视角/遮挡下分别检查角色位置、朝向和环境关系；限定需显示的对象与范围，避免为显示玩家而意外暴露本应隐藏的信息。
7. 世界内操作指示先核对目标真实位置、深度与屏幕投影：钓鱼例将量表改成鱼影/涟漪目标，需从侧视和俯视验证目标环对齐鱼的深度，再加鱼钩动画和鱼线关系。不要仅让提示在某一个镜头看似重合；投影方法、拉动输入和成功判定按项目规则实现，原帖未完整证明。
8. 卡牌可组合阴影、平滑跟随、扇形排列、缩窄换图翻转；选中描边/倾斜/烧蚀应表达实际选择或结果，不能触发多次提交。
9. 战斗菜单保持焦点滑动、放大、说明框与真实可执行指令一致；文字可用逐字/标点停顿和关键词强调，信息不能仅依赖抖动或颜色。
10. 稀有卡牌揭示可从蓄力、翻面暂停到同步符文/闪电突出奖励。将传说卡牌“出框”视为视觉效果，不推断必须真实 3D。
11. 切场时把显示过渡与切场正确性分开：DbqZZNQz95x 实见游戏区域黑屏后淡入走廊，正文称可掩盖出生位置闪动，但这不证明根因已修复。迁移时按项目区分遮蔽、切换/准备和恢复显示，只有目标场景与所需出生点、相机等真正就绪才解除遮挡，不只等待一个固定动画时长。是否锁输入由项目决定；若锁定，正常完成和失败/取消路径都要能恢复到可操作状态。这个状态组织是实施建议，不是从视频还原的加载顺序，也不要求补上未证的淡出。

- DPjC2p_jDK- 只确认模式开启态与恢复普通显示的对照，触发输入、持续时间、距离、遮挡/穿墙规则和 shader 未核验；蓝暗/青绿只是此例配色，不能设为通用规范或据此推断可交互范围。
- 对话跳过、子菜单结构和完整卡牌战斗均未在来源核验；如果需要这些能力，按项目另行实现并标注。

- DemTrHmK44j 仅确认更大、更近岸及 ripples 标签；不补涟漪外形、大小/距离数值，也不把同帖新增动物、武器和烹饪功能拼成效果优化步骤。

## 验收

- [ ] 切场在正常、慢加载和失败/取消情形下，不会过早显露未就绪场景或永久黑屏；错误应有可恢复处理。遮挡关闭或调试检查时，出生点和相机正确性仍需单独验证。
- [ ] 反复进出、切换中再次触发和持续按键不会重复切场、误操作目标场景或遗留输入锁；按项目既定规则恢复显示与控制，不把原帖未展示的锁输入作为必选机制。
- [ ] 鼠标、键盘/手柄适用输入下焦点唯一，按下/松开/取消/失败不会误提交。
- [ ] 连续切换、关闭再开、拾取竞态与重复点击不会丢状态或双重奖励。
- [ ] 反复踩入/离开压板、门运动中反向触发时，门体显示、碰撞与可通行状态仍一致；门口被占用按项目原规则处理，不被粉尘或屏震隐藏。关闭镜头反馈后仍能识别门的状态。
- [ ] 文字和选择结果在减少运动/跳过动效（如项目支持）时仍完整可读。
- [ ] 世界内指示从不同视角/目标深度观察仍与可操作目标一致；动画不会掩盖真实交互范围或错报成功。
- [ ] 临时识别模式反复进入/退出后不残留调色或轮廓，资源被拾取/消失后提示同步清理；对照既定目标集合、距离与遮挡规则，防止意外泄露隐藏信息或让高亮被误解成可直接拾取。比较普通/识别模式下的发现性与路径可读性，不仅靠颜色评价成功。
- [ ] 遮挡角色的圆形窗口与轮廓方案在同一相机/遮挡条件下独立比较，检查移动、遮挡边缘进出与多个前景物体下的位置/朝向可读性及效果清理；按设计确认不会额外显示隐藏敌人或资源，不用评论投票代替验收。
- [ ] 在真实观察距离、相机与背景下能辨认设计上应发现的目标；尺寸/位置/提示分别对照，涉及碰撞、生成位置或风险变化时另列玩法验收，不只凭更显眼宣称整体更公平。
