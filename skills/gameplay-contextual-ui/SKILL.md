# 游戏内交互、卡牌与对话

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 看不出可交互、悬停、选中与提交成功的区别，或设计上应能发现的目标混入水体/背景而难辨。
- 卡牌、菜单或对话动画隐藏真实焦点/进度，或世界内目标圈与目标深度/位置错位。

## 先确认的输入

当前交互状态、真实提交/拾取结果、输入设备、焦点对象、世界/UI 层级与动效偏好。

## 分步机制

1. 先列可用、聚焦、按下、选中、成功/失败状态；表现绑定实际状态而不是单纯鼠标经过。
2. 实体按钮以 press down、overshoot、ripple 和成功 reward 分层；按下反馈不等于执行成功。
3. 拾取物根据已有距离/朝向条件显示提示，成功后更新世界物体与持有状态；F 是原帖示例按键，实际按键应取项目映射。
4. 当目标本应可发现时，先在实际相机下检查屏幕尺寸、出现位置与背景对比，再考虑涟漪等环境提示；水下捕猎例中放大鱼、让鱼更近岸是已见对照。视觉放大与碰撞体/生成位置改变要分开，后者可能影响可达性和难度，需按项目规则明确验证。这个优先顺序是迁移提炼，不意味着所有隐蔽/狩猎设计都要消除发现难度。
5. 世界内操作指示先核对目标真实位置、深度与屏幕投影：钓鱼例将量表改成鱼影/涟漪目标，需从侧视和俯视验证目标环对齐鱼的深度，再加鱼钩动画和鱼线关系。不要仅让提示在某一个镜头看似重合；投影方法、拉动输入和成功判定按项目规则实现，原帖未完整证明。
6. 卡牌可组合阴影、平滑跟随、扇形排列、缩窄换图翻转；选中描边/倾斜/烧蚀应表达实际选择或结果，不能触发多次提交。
7. 战斗菜单保持焦点滑动、放大、说明框与真实可执行指令一致；文字可用逐字/标点停顿和关键词强调，信息不能仅依赖抖动或颜色。
8. 稀有卡牌揭示可从蓄力、翻面暂停到同步符文/闪电突出奖励。将传说卡牌“出框”视为视觉效果，不推断必须真实 3D。

## 适用限制

- 对话跳过、子菜单结构和完整卡牌战斗均未在来源核验；如果需要这些能力，按项目另行实现并标注。
- 普通 Play 菜单、泛动画不在本技能选材方向；原帖未验证的 shader/引擎实现不能冒充已知技术栈。
- DemTrHmK44j 仅确认更大、更近岸及 ripples 标签；不补涟漪外形、大小/距离数值，也不把同帖新增动物、武器和烹饪功能拼成效果优化步骤。

## 验收

- [ ] 鼠标、键盘/手柄适用输入下焦点唯一，按下/松开/取消/失败不会误提交。
- [ ] 连续切换、关闭再开、拾取竞态与重复点击不会丢状态或双重奖励。
- [ ] 文字和选择结果在减少运动/跳过动效（如项目支持）时仍完整可读。
- [ ] 世界内指示从不同视角/目标深度观察仍与可操作目标一致；动画不会掩盖真实交互范围或错报成功。
- [ ] 在真实观察距离、相机与背景下能辨认设计上应发现的目标；尺寸/位置/提示分别对照，涉及碰撞、生成位置或风险变化时另列玩法验收，不只凭更显眼宣称整体更公平。
