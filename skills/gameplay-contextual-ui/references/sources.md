# 游戏内交互状态与提交反馈

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 按下、焦点或进度动画看似成功，却与真实交互/指令执行状态不符。

## 先确认的输入

可用/聚焦/按下/执行中/成功/失败事件、真实提交结果、实际输入映射、目标和焦点归属；按住操作另确认保持/释放/取消条件。

## 分步机制

1. 先列真实状态与输入许可，显示只订阅状态；聚焦、按下和执行成功不能互相代替。
2. 按钮按需组合 press down、overshoot、ripple 和结果确认；形变引用共享机制，奖励只有实际成功时显示。
3. 按住操作显示按下、保持进度与完成，明确松开/取消/失败的去向。Hold to Charge 来自按钮例，不证明资源消耗或具体阈值；不把动画填满当实际成功。
4. 拾取物按既有距离/朝向显示提示，成功后同步世界物体与持有状态；按键取项目映射，不硬用来源 F。
5. 战斗指令菜单用焦点滑动、放大和说明框表达当前可执行选择；不把它强制套成卡牌扇形排列，不补未证子菜单或战斗执行逻辑。

## 适用限制

- 按钮声音未核听，持续按住阈值未知；手电距离/角度未知，不将交互展示当完整引擎实现。
- 战斗菜单部分编号缺失，子菜单构造与战斗执行未展示；泛 Play 菜单和网站 UI 不在此技能。

## 验收

- [ ] 适用鼠标/键盘/手柄下焦点唯一，按下/保持/松开/取消/失败不误提交。
- [ ] 重复点击、关闭重开及拾取竞态不双重发放/丢状态；不足条件不播成功。
- [ ] 提示和指令可用性与真实状态一致，减少运动后仍可理解结果。
