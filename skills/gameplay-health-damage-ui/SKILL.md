# 生命血条与浮动数值

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 生命值变化突兀或损失量不易理解。
- 密集伤害、治疗或得分浮字遮挡对象，或事件类型、普通/暴击无法区分。

## 先确认的输入

真实 HP/最大 HP 与变更事件，以及各浮字对应的事件类别（伤害/治疗/得分）、真实数值、来源、显示空间、字号范围和同时发生事件的顺序。仅做得分浮字时不用接入血量或残影条流程。

## 分步机制

血条需求使用第 1、2 步及可选第 7 步；浮字需求使用第 3–6 步，按事件类型读取对应验收，不要求所有场景接入全部分支。

1. 将真实值与显示动画分离。真实扣血立即生效，前景条可平滑追随；残影条保留刚损失部分再追赶。将“受击后等待多久”与“开始追赶后花多久”分为两个独立参数，明确连续伤害对等待/排空各自如何重置，避免把延迟和动画时长混成一个数值。
2. 单独处理治疗、最大血量变化、死亡与复活；不要让损失残影错演成又受一次伤或显示超上限。
3. 伤害、治疗、得分复用同一浮动数字表现机制，但从各自真实事件取值，不混成一个业务结算。先以可读字体显示数值，再选择弹出、短程运动和淡出；弧线/重力是可选轨迹，不以复杂运动代替识读。DcwUHp0O85b 的弹球得分例依次展示文字、位置补间、旋转、淡出、缩放入场与配色，并给无效果对照；可见 +100 上浮、轻微倾斜、淡出、缩放入场及最终绿色。这是制作展示的标签顺序，不是要求一次浮字先淡出再入场；动画相位按实际事件组织。
4. 如需按数值大小映射字号，为每种事件分别设上下限，不让高分值自动拥有重击表现。按事件类型增加形状/文字或图标，颜色只作辅助；暴击标记仅用于真实暴击事件。原帖的绿色得分不能直接当成项目通用规范，也不能让 +100 同时被误认成治疗。
5. 选择错开、分区或合并策略。合并时清楚表示同一类型的总量/事件数或短窗累计，避免把多次命中或得分误读成一次；不同类型及不同归属对象不要无说明混加。这属于迁移建议而非原作者已验证结论。
6. 同场景对比无效果/有动效以及稀疏/密集事件，确认数字仍关联正确对象，且不挡危险区或球的下一运动方向。只有涉及血量时再考虑叠加血条闪光等反馈，不为得分显示引入扣血流程。

7. 若项目使用 Godot 且需要延迟血条，可参考 DcZxryBoCFw 的实见搭建顺序：准备边框/血量/暗底纹理，配置主 TextureProgressBar 的 over/progress，再以第二层 TextureProgressBar 显示延迟损失段，最后绑定真实生命变更。两个层的范围、值和布局须与项目实际规则一致。视频展示了 tween.kill / create_tween，但未证明完整取消/重启逻辑，实施时应检查现有 tween 归属并做重复扣血测试，不照抄成已验证代码。

## 适用限制

- 0.75 秒 drain、0.4 秒 ghost/delay、50%/25% 颜色阈值只来自特定例子。Godot 案例的 ghost_delay=0.25 秒与 ghost_time=0.45 秒分别是等待与排空时长，同样不是默认最佳值，不用新数字覆盖其他来源的参数。
- Godot 演示脚本与正文提供的 GitHub 项目均未运行；后者未读取/审计，不能把界面截图或部分 API 名称当作实现正确性证明。
- 弹球得分例未给出动画时间、曲线或旋转是否随机；+100 与绿色仅是案例显示，不是通用数值/颜色规范，也不证明底层计分已验证。
- 不要编补 DemP6LfRbug 第 3/5/8 步或 DcDs7f9uaqo 缺失淡出参数；引擎声明不等于实现验收。

## 验收

- [ ] 连续扣血、同帧治疗与受伤、致死/复活、最大生命改变都正确收敛。
- [ ] 最小字号、低对比背景、色觉差异与密集多人事件下仍可识别数值/类型。
- [ ] 取消动画或场景切换不残留数字；伤害、治疗、得分各自的显示总量与对应真实事件一致，动画不负责结算或重复计分。
- [ ] 同屏多碰撞点的得分各归其主，正数得分与治疗不会只靠同一种颜色区分；位移/旋转/入场/淡出既可识读又不会遮住下一接触点。
- [ ] 分别调等待时间和排空时长时只有对应阶段改变；等待中与排空中的再次受伤、治疗/致死，以及 tween 被取消后的两层血量都能正确收敛。
