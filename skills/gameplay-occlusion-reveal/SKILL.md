# 角色遮挡检测与局部显露

本文件区分遮挡触发条件与触发后的可见表达。来源支持有限游戏示例及作者解释，不是完整轮廓可见性求解或已运行的引擎实现；工程步骤与验收须在目标项目另行验证。

## 触发条件

- 前景遮住玩家，需保持位置、朝向和与环境关系可读。
- 单点遮挡在小边角就触发大面积透视，角色仍有可见部分却频繁开效果。
- 已有遮挡提示在移动、姿势变化或退出遮挡后抖动/残留，需要区分查询、聚合和渲染状态问题。

## 先确认的输入

实际相机与需要保护可见性的角色、采样点及其随姿势/尾部变化的位置、可遮挡物集合、透明物/自身碰撞体的查询策略、聚合条件、现有显露效果与退出状态。先确认允许显示的信息，不把玩家提示扩成隐藏敌人/资源透视或改变潜行判定。

## 分步机制

1. 在相同相机/路线复现全遮、部分遮挡与小边角误触发，显示采样点和查询线。先定位是采样位置、遮挡对象还是触发聚合过于敏感，不先扩大透视窗口。
2. 为项目角色选择能代表其姿态的采样点并定义有效查询。Db--r9yPbU3 作者由相机到角色的单射线改为头、尾、身体三条射线；实际点位、碰撞层与透明物规则未给出，应在项目中明确并调试，不能套给任意角色体型。
3. 将各查询结果聚合为触发条件。该来源的候选规则是“三个采样均被遮挡才开启”，任意一个无遮挡则不触发；它不是“每个像素都被遮挡”的证明。无效/越出视野的采样如何处理需要独立规则，不默认为完全遮挡。
4. 让已有显露表现读取聚合结果，再比较局部透视窗口、角色轮廓等表达。Dd7GYLGPlon 只提供两种显示方案比较，没有赢家或检测算法。窗口范围应足以辨认玩家且不过度打断场景；不把新来源的三射线规则归给这条旧帖。
5. 退出遮挡、角色/相机改变或对象失效后恢复原显示；检查小幅移动时的反复切换。若项目需要稳定化，可单独评估滞回/防抖或别的聚合阈值，并记录引入的显露迟滞；来源没有提供这些机制或参数。
6. 分别验收判定与表达：先看采样是否按已声明条件触发，再看玩家剩余的可见片段是否足以跟踪。三采样规则若漏掉重要轮廓，不能仅因逻辑满足就宣称可读性正确，应调整项目方案并保留对照。

## 来源差异与适用限制

- Db--r9yPbU3 可见旧版小边角也打开大点阵窗口/描边，作者解释原单射线遇障即开；随后 debug 与字幕解释头/尾/身三射线 ALL 遮挡规则；末段可见部分角色露出时前景保持实心、不再开大遮罩。这是有限修复结果，非同步输入回放或穷尽回归。
- 初始演示有被遮角色的透视效果；修复后的完全遮挡开启动作并未作为独立完整回归验证。三点是启发式，不保证完整轮廓遮挡、零误判、最优射线数或更低成本。
- 未核源码、具体射线实现、碰撞层、点偏移、更新频率、淡入淡出、滞回/防抖或 CPU 数据。点阵外观不证明某种 shader，屏幕显露不等于相机移动、物理穿透或敌人发现规则变化。
- Dd7GYLGPlon 的同猫/同场景圆形窗口与白轮廓 A/B 仍只有表达证据：半径、线宽、触发/遮挡算法未知，作者询问而未给赢家。新来源不得填补它的缺口。音频均未核听。

## 验收

- [ ] 按所选聚合规则复现全遮、部分遮挡和小边角；采用三点 ALL 方案时，任一点清楚则不触发、三点均挡才触发，另测无效样本，不用它替代轮廓可读性判断。
- [ ] 头/尾/身体动作、细遮挡物、长形角色、画面边缘和多个前景物体下，样本与角色仍对应；剩余可见片段足以定位/辨认朝向，否则调整方案。
- [ ] 同路线/相机对比原判定与新判定，分别记录误开、漏显及状态切换；小幅移动无不可接受闪变。稳定化若使用，应说明它的响应取舍，不能声称源帖已验证。
- [ ] 角色/相机切换、离开遮挡及对象销毁后不残留窗口/轮廓；效果不额外显露未授权隐藏对象，不影响物理碰撞、相机位置或潜行检测。
- [ ] 局部窗口与轮廓方案分别检查位置/方向/环境关系可读性，保留实际测试结论，不以作者或评论偏好定赢家；性能按项目测量。

## 组合而不复制

- [世界目标发现性](../gameplay-world-readability/SKILL.md)选择资源/交互点的发现提示，不拥有本页遮挡采样和显露状态。
- [镜头反馈](../gameplay-camera-feedback/SKILL.md)改变临时画面偏移，不替代角色遮挡判断，也不要求为了显露自动移开相机。
- [接触视觉与遮挡预算](../gameplay-impact-visuals/SKILL.md)处理装饰效果遮住角色时的删减；别先制造过多粒子，再用透视补救。
