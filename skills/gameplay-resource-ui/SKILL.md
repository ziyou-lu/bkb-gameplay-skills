# 法力、体力、冷却与蓄力状态

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 技能恢复了但看不出来，或视觉已恢复却仍不能用。
- 法力/蓄力只显示静态数字，消耗确认弱。

## 先确认的输入

资源真实值、技能可用条件、冷却时钟、消耗失败/取消事件和 UI 生命周期。

## 分步机制

1. 明确可用、消耗、冷却、恢复、禁用等状态，展示层只订阅真实变化，不用动画是否完成代替资源规则。
2. 法力宝石消耗可局部闪光/碎裂，恢复用回弹/压缩；用形状和文字保留低特效辨认。
3. 冷却选择扫过填充、变暗和倒计时组合，明确计时取真实规则时钟还是受慢动作影响。
4. 恢复时先保证真实可用状态，再播短确认动画；避免动画抢焦点或挡住下一次点击。
5. 蓄力按钮展示按下、保持进度与完成奖励，处理松开/取消/失败；阈值由项目定义而非从按钮视频猜。
6. 将血量显示交给生命血条技能，避免同一平滑/残影机制复制成资源 UI 的第二套实现。

7. 攀爬等持续动作可把体力读数收紧到角色附近的圆环/短条，并比较原版遮挡。将成长/收集徽章与实时资源读数分层是本库的设计提炼；红色消耗段、外缘小点不能被擅自解释为残影延迟或固定点数公式。

## 适用限制

- DeXJvO9kg94 只是 UI 演示且字幕不全；DeFICP0DMwZ 恢复参数未知。
- 未见源码执行或完整战斗资源逻辑，不宣称视频已验证并发和暂停行为。

## 验收

- [ ] 持续攀爬、体力耗尽/恢复及成长数值增加时，实时读数不被徽章堆叠遮挡，仍对应真实资源。

- [ ] 重复消耗、冷却重置、暂停/慢动作、切场景后与真实可用性一致。
- [ ] 资源不足/取消不播放成功碎裂或奖励，恢复确认不阻塞连续操作。
- [ ] 极短和极长冷却均可读，显示取整不会误报提前可用。
