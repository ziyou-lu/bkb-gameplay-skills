# 视觉材质感与接触响应诊断

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 网格已有凹陷或损伤，但碰撞后状态仍与期望材质感不符。
- 物体接触前运动已符合目标，但落地后回弹、硬度或稳定过程不符，需要单独检查接触阶段。
- 需要判断问题能否仅靠表现解决，还是明确需要改变局部接触行为。

## 先确认的输入

入射速度/方向、接触对象和所用接触材质、碰撞后状态、当前网格与碰撞体的各自职责，以及是否明确允许改变物理规则。把“外观变形”和“接触响应变化”分别记录；倒伏场景先固定接触前的运动条件。

## 分步机制

1. 保留同条件原版，分别观察可见外观和碰撞后状态；涉及网格损伤时，不用“看见凹陷”判定物理已经具有弹性，单纯回弹问题无需先增加损伤表现。
2. 按接触问题选择候选，不强制每种物体用同一方案：
   - 视觉损伤已有但碰撞过硬：DcCFXGItxdJ 作者称修改 NVIDIA physics package，允许少量接触穿入近似金属部分弹性。它是候选方向，不是可复刻算法或通用容差建议。
   - 落地材质响应不符：DUbEXCrDTID 展示 Physics Material 面板与 ADD A SUBTLE BOUNCE 字幕。将材质回弹作为独立候选；本来弹得过高的物体可能需要减少而不是增加回弹，不把“微回弹”设成所有物体目标。
3. 若目标只允许纯表现改动，保留真实接触规则并转到视觉形变。只有明确允许物理变化时，另建局部、可回退的接触实验，不能悄然放宽全局碰撞容差。
4. 保持接触前速度、角度与接触对象相同，按需分别开关视觉网格方案和接触实验，比较碰撞后状态并检查无关物体是否受影响。材质分支单独修改并记录接触配置，不在同一对照里又改重心与施力点。
5. 检查薄障碍、高速、擦碰和重复碰撞；发现非预期穿透、卡住、弹飞或稳定性问题时回退候选方案，不让视觉改善代替物理正确性。

## 适用限制

- 修改物理包与弹性近似只获作者字幕说明，未见代码、具体 API、穿入量、碰撞体更新方式或参数，正文承认仍需完善。
- 局部穿入画面不证明完整软体、真实金属材料模拟、稳定接触解算或任意场景可用；不能从外观推断碰撞体随网格更新。
- DUbEXCrDTID 的材质面板和微回弹字幕不提供可靠恢复系数、摩擦或组合规则；最终倒树结果不是回弹高度测量，也没有隔离材质与重心/施力点的贡献。粉尘/木屑和更好音频是未来计划，不作为该来源已完成内容。
- 没有独立量化或运行验证，音频未核听。受控对照、回退及边界测试是本库迁移建议，不是来源已经通过的验收。

## 验收

- [ ] 涉及视觉损伤时，相同初始条件下分别开关视觉与接触方案，能区分外观差异与碰撞后状态差异；材质单项问题不强加视觉损伤。
- [ ] 薄障碍、高速、擦碰和重复碰撞中没有非预期穿透、陷入/卡住或弹飞，无关物体不受影响。
- [ ] 物理变化的范围和预期结果明确可回退，不把局部演示扩成全局容差修改，也不把凹陷/局部穿入视为稳定性验证。
- [ ] 材质实验保持接触前条件一致，落地后的回弹和趋于静止符合目标，无意外连续弹跳或抖动；不把一组倒伏结果当单变量证明。

## 组合而不复制

- 首次接触前的倒伏方向/重量感问题使用[重心与施力诊断](../gameplay-prop-toppling-dynamics/SKILL.md)。本页只处理接触发生后的响应，不扩成所有刚体调参的入口。

- 主体碰撞正常但枝条等突出部漏接触时，使用[突出部接触覆盖与响应](../gameplay-prop-appendage-contacts/SKILL.md)，不把局部覆盖问题改成放宽接触容差。

- 需要构建有连接与层间弹簧的可压缩表面时，使用[交互承载面](../gameplay-deformable-support/SKILL.md)，不把接触穿入实验当作承载结构。

只在需要相应机制时读取，沿用其事件与预算约束：

- [接触位置与粒子反馈](../gameplay-impact-visuals/SKILL.md)
