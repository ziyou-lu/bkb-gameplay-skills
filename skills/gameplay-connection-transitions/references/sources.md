# 连接关系与挂脱轨迹

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 已有连接/脱开功能突然跳到最终形状，或绳端显示与真实关节状态不一致。

## 先确认的输入

两端锚点、未连接/连接中/已连接/脱开状态、实际关节/牵引/碰撞职责以及取消/失败事件。

## 分步机制

1. 先确认真实连接的成立和解除条件，再把过渡显示接到这些状态；不要为动画先显示成功后才检查是否连接。
2. 按项目需要让抛出/连接过程可见；DKrymGwPEVi 明确抛钩沿弯曲路径，实见成弧链条及脱开中间态，不要求写成抛物线或完整绳索物理。
3. 持续更新两端锚点与实际关系，分清连接中与已连接；失败/取消后清除未完成表现。上述状态组织是迁移建议，不是原帖代码验证。
4. 较早补证帖提供直绳变下垂弧形及短绳参考，但不可用来补全主帖缺失回收句或推定运行时序。

## 适用限制

- 主帖完整回收过程、曲线算法、视觉与关节物理分工未核验，无时长/响应实测或音频核听。
- [DJ9eQbOP30H](https://www.instagram.com/p/DJ9eQbOP30H/) 仅为同机制较早补证：LineRenderer 字幕、RopeRenderer 的 SegmentCount/MaxSagAmount/SagDistanceThreshold 名称与短绳展示，不是已审代码或通用参数；不另计来源。

## 验收

- [ ] 连接、脱开、失败/取消和重复触发后，绳端、状态提示与实际关系一致。
- [ ] 移动锚点、场景中断和关系失效后不残留旧绳或错误连接态。
- [ ] 只改表现时原牵引/碰撞规则不变；若改关节生效时机另列物理与控制验收。

## 组合而不复制
