# 输入响应与动作相位

## 触发条件

- 输入后首个可见响应太晚，但整段倍速又损失主体动作或收势重量。
- 动画堆积了不传达操作信息的表演，需要区分可删准备与玩法必要前后摇。

## 输入与前置条件

输入接收、首个可见响应、关键姿态、实际命中/开火、恢复和取消事件；标出哪些准备段承担蓄力、敌人预警、冷却或反制窗口，哪些只是视觉表演。

## 实施步骤

1. 记录输入接收、首个可见响应、动作生效、恢复与取消的时间点，生成一条可回放的动作时间轴。
2. 将动画拆成准备、主体和收势。给每个准备动作标注用途：蓄力、敌人预警、武器操作或纯表演；只把不承担规则/信息的段落列为删减候选。
3. 先缩短或移除冗余持枪/绕枪等表演，保留清楚的伸臂、射击关键姿态和回立姿。事件轨道仍以项目实际生效节点为准，不让剪帧自动搬动伤害或冷却。
4. 做原版、局部压缩准备、整体加速三个版本。固定美术与玩法时序，比较响应、主体可读性和收势重量；必要的蓄力与反制窗口不得随表现优化删除。
5. 把最终事件与动画重新对齐，测试连发、取消与恢复。需要更早真实生效或更高射速时，作为单独玩法变更处理。

## 调参顺序

分别暴露准备段压缩比例、主体节奏和收势时长。先改准备段，再调收势；不用通用三等分比例或“一帧响应”目标。以项目测得输入到显示/生效延迟和关键姿态可辨认性决定取舍。

## 失败处理

若响应仍慢，先查输入/状态进入与事件调度，而非继续压缩动画。若武器方向难读，回退到关键姿态再调整 smear；若反制窗口被缩短，恢复规则时间点。

## 验收

- [ ] 分别比较原版、只压缩冗余准备段与整体加速，独立记录输入、首个可见响应、真实生效和恢复时刻。
- [ ] 主体动作、关键姿态与收势仍可读，不以“看起来更利落”代替时序测量。
- [ ] 必要蓄力、敌人预警和反制窗口未被误删；纯表现优化不跳过冷却/前后摇或改变射击频率，预期玩法变化单列验收。
