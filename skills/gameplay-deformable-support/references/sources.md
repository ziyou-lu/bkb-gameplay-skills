# 可弯曲与压缩的交互承载面

来源以 debug 实机和字幕解释层状结构，并未展示旧新版 A/B。以下是基于该结构的迁移设计与待验收流程，不是已运行的引擎实现，也不代表性能或真实性已提高。

## 触发条件

- 车轮或其他载荷经过床垫状表面时，需要承载面在局部弯折并沿厚度压缩，同时继续提供物理支撑。
- 已有分段柔性承载面发生接缝分离、穿落、过度振荡或卸载后漂移，需要定位连接与接触问题。
- 若只想看起来压扁而不改变真实支撑，使用[视觉形变](../../gameplay-motion-deformation/SKILL.md)，不要引入整套连接刚体模拟。

## 先确认的输入

项目允许的物理变化、承载面尺寸与分段尺度、刚体质量、层内连接关系/自由度、边界承载方式、层间弹簧连接与压缩范围、载荷及其接触形状、碰撞过滤、步长和解算预算。来源没有提供这些工程参数，不能照画面反推。

## 分步机制

1. 先明确要模拟的行为是局部弯曲、厚度压缩还是两者，给出车辆中心/边缘加载的最小场景。保持载荷、轮胎接触和场景条件可重复，不在同一实验中又改转向、摩擦与碰撞几何。
2. 建立单层分段刚体和连接关系，定义允许的相对运动及边界承载。作者以 3×5 网格和 joints 解释可弯曲层；它是来源结构示例，不是最优分辨率或已知关节类型。先检查单层接缝和载荷传递，再增加复杂度。
3. 需要厚度压缩时，再引入另一层并用层间弹簧连接；明确连接对应、初始间距、限位与回弹目标，分别观察层内弯折和层间压缩。刚度、阻尼、质量与碰撞过滤须由目标引擎试验，不把任一参数命名成来源给出的默认值。
4. 让载荷沿中心、边缘和分段接缝移动，记录支撑连续性、下陷和卸载响应。出现穿落、断开或不受控弹飞时，检查接触、连接、限位与解算设置，不能只放大视觉模型遮住缝隙。
5. 在实际载荷范围、速度和物理步长下评估稳定性与成本；调整分段数或约束复杂度后重新检查承载功能。若需要最终连续网格，另定义其与物理段的映射并核对外观/接触，不从 debug 画面声称已知蒙皮或 shader。

## 适用限制

- DVOcLi2EVOK 可见车轮所在区域局部向下弯折、相邻段角度不同，车轮在画面中仍处于承载面上；这是游戏内载荷演示，不是独立接触/稳定性测试。
- “一层 3×5 刚体由关节连接，另一层叠加并用弹簧允许压缩”来自字幕；部件一起解释，不是逐步开关或旧新对照。没有核验精确拓扑、关节类型/限制、质量、尺寸、碰撞过滤、弹簧系数、解算设置或恢复时间。
- 没有正常渲染对照、性能数据或真实材料标定，不宣称通用软体、体积守恒、准确床垫物性或 3×5 最优。评论者自己的轮胎方案不是本作者床垫实现证据，音频未核听。

## 验收

- [ ] 中央、边缘和接缝受载时有约定的局部形变与支撑，段之间不非预期分离，轮子不穿落。
- [ ] 载荷移动和卸载后，连接保持、压缩限位与恢复行为符合项目目标，没有累积漂移或不受控振荡。
- [ ] 目标载荷、速度、接触形状、步长/解算配置分别验证；成本有项目实测记录，不把来源结构当性能承诺。
- [ ] 若接入连续视觉网格，debug 接触面与最终外观同时可查，不用外观补丁掩盖穿透或脱节；不需要真实物理变化的场景保留轻量视觉方案。

## 组合而不复制

- [视觉形变](../../gameplay-motion-deformation/SKILL.md)管理不改变物理的 squash/stretch；本入口的承载几何会参与接触，不能共用“碰撞始终不变”的验收结论。
- [移动接触表示](../../gameplay-locomotion-contacts/SKILL.md)处理轮胎自身形状覆盖，表面连接/弹簧问题不靠换轮胎表示代替。
- [接触响应诊断](../../gameplay-contact-response/SKILL.md)区分视觉损伤与碰撞反应，不提供本页的层状承载结构；也不能以放宽全局穿透容差替代支撑连接。
