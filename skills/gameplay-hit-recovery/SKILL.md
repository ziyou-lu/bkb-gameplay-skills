# 连续受击恢复与脱身策略边界

## 效果预览

连续受击，被围在原地；达到本例阈值，推开后脱身；玩法规则示例｜计数到阈值触发无伤害脱身。

左侧为使用前，右侧为使用后；4 秒循环，用途示意（非引擎实测）。

![被连着打，达到条件后挤出空间：使用前后对比](assets/before-after.gif)

## 触发条件

- 角色连续受击或被围在角落，按既有规则难以恢复操作，需要评估机制而非只增强受击特效。
- 已有阈值脱身机制，需区分触发、结束与提示；若只需要受击表现，回到[近战编排](../gameplay-melee-feedback/SKILL.md)。

## 输入与前置条件

被接受的受击事件、角色可操作/硬直状态、伤害与控制规则、计时所用时钟，以及项目是否明确要求新增或修改保护。阈值策略另需统计窗口、计数规则、重置条件、脱身影响范围与是否造成伤害。

## 实施步骤

1. 复现角落与开放空间的连击，确认是反馈难读、恢复状态错误，还是规则确实不给脱身空间；纯表现任务不增加免疫或击退。
2. 对需要阈值脱身的项目，定义被接受受击的计数单位、统计窗口、阈值、重置及再触发许可。持续碰撞回调不能代替一次真实受击。
3. 每次有效受击更新统计，清除窗口外记录，达到阈值且许可成立时只触发一次脱身；建立待统计、脱身中、恢复统计状态。
4. 脱身动作可用无伤害击退恢复间距；按项目设定目标范围、阻挡和控制恢复，不把吼叫自动变成反击伤害或无敌。
5. 普通受击与脱身使用不同提示，提示读取真实状态。死亡、重生、卸载和暂停按选定时钟/重置约定处理计数及表现。

## 调参顺序

分别调统计窗口、受击阈值和脱身距离；用相同攻击序列比较可操作恢复与风险降低。先确定窗口是否滚动及阻挡事件是否计入，再调数值，避免阈值变化掩盖计数错误。

## 失败处理

连续重叠瞬间触发时先查事件去重；无限反复脱身查重置/再触发许可；墙角击退无效查空间约束并保留设计取舍，不擅自加入伤害或穿墙。

## 验收

- [ ] 阈值策略及规则变更已明确；仅改表现时不改变原伤害、击退或可操作状态。
- [ ] 统计窗口、阈值上下边界和脱身结束分别检查，持续碰撞不被误计为多个真实受击事件。
- [ ] 若采用阈值脱身，实际伤害为项目明确规则；采用无伤害脱身时吼叫不得额外造成伤害。
- [ ] 多攻击者、重置、死亡/重生及项目支持的暂停后状态可恢复，提示不比实际脱身状态持续更久。
- [ ] 对照角落与开放空间记录效果，不以局部脱身演示代替全局难度或公平性验证。

## 组合与边界

- [近战受击编排](../gameplay-melee-feedback/SKILL.md)负责接触表现，不拥有恢复规则。
- [攻击预警与反制可读性](../gameplay-attack-readability/SKILL.md)负责读招；看得清下一招与拥有脱身机制分别检查。

[受击后保护窗口](../gameplay-post-hit-protection/SKILL.md)按首击后的时间窗口阻挡伤害，与本页统计阈值脱身分别定义。
