# 冲刺路径与残像反馈

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 冲刺看起来像普通位移，或重拖尾吞没角色与落点。

## 先确认的输入

真实冲刺起止、速度/距离、方向、碰撞与角色视觉层，残像的生成/清理预算。

## 分步机制

1. 固定同场景同动作与实际速度建立无效果基线，先辨认起点、路径和结束位置。
2. 按需求选择预备、方向性拉伸、残像与速度线；如果预备改变输入响应，必须单列规则变化，不把它当免费视觉增强。
3. 以 Light trail/Heavy trail/Ghost dash 等替代样式独立对照角色轮廓、轨迹密度与路径，而非从轻到重的必然升级。
4. 冲刺结束、打断或传送时清理临时形变/残像；高速屏幕效果复用速度镜头，不另造相同后处理机制。

## 适用限制

- 首帖只有分层标签，声音未核听、源码未执行；未给出的时间和数量不补全。
- DX6_8HIo_GT 的 Heavy 样式实见密残影与水平线，Ghost 瞬间未完整捕获；透明度/数量/时长未知，无敌帧只是评论联想，不是规则证据。

## 验收

- [ ] 同动作、速度、场景下比较各样式，能说明角色轮廓、路径、落点与遮挡差别，不以更多粒子判胜。
- [ ] 起止、连续冲刺和打断后不留残像或缩放，未授权的距离/速度/碰撞/无敌状态不变。
- [ ] 低特效与减少镜头运动后仍能辨认冲刺状态和下一目标。

## 组合而不复制

- [事件形变](../gameplay-motion-deformation/SKILL.md)：方向拉伸不改变碰撞
- [速度镜头](../gameplay-speed-camera/SKILL.md)：屏幕速度线/FOV/模糊统一owner
