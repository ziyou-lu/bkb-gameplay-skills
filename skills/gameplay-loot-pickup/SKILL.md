# 掉落物吸附与拾取确认

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 奖励已生成，但玩家看不出它从何而来、是否可取或是否已经收到。
- 已有金币吸附，但视觉到达与实际入账混淆，或不可达/拾取失败仍播放成功反馈。

## 先确认的输入

权威掉落生成事件、对象归属与价值、可拾取条件、目标接收者、实际成功/失败事件及背包限制。需要吸附时另确认启动范围、路径/障碍规则、目标移动或消失时的处理。

## 分步机制

1. 分开生成、可拾取、引导/吸附、实际拾取确认。此状态划分是迁移建议，DeikuCgOkof 只保留 Magnet、Sound、Sparkle，未展示完整业务流程。
2. 让生成位置和来源可追踪，但不在表现层二次生成经济奖励。对象破坏或宝箱揭示已经确认生成时，本页只接收对应对象/事件。
3. 若项目已有或明确要求吸附，绑定其真实启动与停止条件再表现趋向接收者的运动。不从来源 Magnet 推定固定半径、自动穿墙或通用曲线；吸附过程不等于已经拾取。
4. 仅实际成功后展示闪光或确认信息；声音是待制作/核听项。数值展示接收已经结算的变化，不因视觉每次靠近目标再次加分。
5. 背包满、目标丢失、吸附中断或对象回收按项目已有规则恢复/清理，区分等待、失败与成功。上述失败分支为工程验收建议，不是来源已证实现。

## 适用限制

- DeikuCgOkof 第 2/5 步缺失；不可补成完整五步教程。
- 吸附半径、路径、障碍处理、分值、背包和并发领取逻辑均未知；音效未核听，没有执行代码。
- 生成/可达性/失败检查来自迁移需要，不代表来源显示过相应系统。若项目没有吸附规则，本页不自动新增。

## 验收

- [ ] 生成、可拾取和成功入账各自有真实事件；视觉靠近/到达不替代实际确认。
- [ ] 两个接收者、重复请求或对象复用按项目归属规则只领取一次，不重复加分。
- [ ] 若使用吸附，在障碍、接收者移动/消失和停止条件下行为符合既有规则；不可达不会假报成功。
- [ ] 背包满、取消或场景中断不遗留永久追逐表现，失败与成功提示可区分。
- [ ] 关闭粒子/数值动效后结果仍正确，原经济数值没有因表现改动而变化。
