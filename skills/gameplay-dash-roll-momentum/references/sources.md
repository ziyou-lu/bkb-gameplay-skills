## 工程实现选项（非来源公式）

下列是便于落地的设计候选，不是作者算法、已测试代码或默认参数；项目可选等价的有限映射。所有阈值、曲线、单位、时长和预算关系都需项目设定。

先验证重力向量有限且非零、支撑法线有限且非零，再将它们归一化。设 `g_hat` 为重力单位方向，`v_in` 为碰撞前角色速度；若选支撑相对参照，先减去接触点的平台速度。取下降速度 `d = max(0, dot(v_in, g_hat))`。用项目定义且满足 `d_high > d_low` 的输入区间构造 `x = clamp((d - d_low) / (d_high - d_low), 0, 1)`，再取 `r = clamp(F(x), 0, 1)`。这只是一种有界归一化，不代表来源给出线性比例。

翻滚目标的一种候选是 `s_roll = min(s_cap, s_base + s_gain * r)`，所有速度参数非负且单位一致。此候选替换前进切向目标，不再叠加原切向速度；若设计要保留已有前进速度，改为另一个明确有界的合成规则，不能同时执行两种规则。对单位支撑法线 `n` 和设计前进方向 `f`，投影 `t_raw = f - dot(f,n)*n`，长度达到项目容差时才归一化；退化则尝试上次有效方向再投影，仍退化就不转换。重新合成速度时保留非穿透处理，不凭映射额外加入离地法向弹射。

储存预算的一种候选是无量纲 `B = r`，只在合格转换成功时设定。翻滚冲刺成功时一次性取出 `B` 并置零，用另一个有界函数映射为速度增益，再限制最终速度；在项目时长后撤销增益。这是“储存动量”的玩法抽象，不是物理能量模型。若项目选速度量、冲量或带衰减的预算，需明确单位、消费及更新规则，不能混算。消费和状态切换必须在同一事务/移动更新中完成，失败时不得只加速不扣预算。

默认候选可限制每个明确动作链只铸造一次预算，链结束清零；若采用其他连招方案，必须定义重新铸造资格、持续时间上限和总速度上限。尤其不能让加速得到的速度无条件回流为新的预算。具体链起止、衰减与上限均是项目决策，不可归给原帖。

## 工作流归属与验证边界

本机制的输入是碰撞前下降速度与翻滚状态，输出是实际切向速度和可消费预算，故不同于冲刺残像、落地表现或平台边缘停留/释放。入口中的单次转换、支撑资格、退化回退、唯一速度写入、预算消费、生命周期复位、有限连招和关卡可达性测试均为工程约束及建议验收，未在来源中被实测证明。
