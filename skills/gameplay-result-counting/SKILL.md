# 结果总分递增计数

本文件是从来源案例提炼的迁移流程，不是作者源码复刻，也未在目标游戏中执行。下面的验收项是实施后要做的检查，不是已经通过的测试。

## 触发条件

- 结果界面需要逐步展示已确认总分，而不是碰撞点的瞬时加分浮字。
- 计数跳过、重复打开或离开界面后显示不一致，或动画刷新被错误用于计分/发奖。

## 先确认的输入

权威结果值、结果确认事件、显示初值、UI 生命周期，以及是否支持跳过；完成与失败展示各遵循项目既定规则，不从动画推断结算。

## 分步机制

1. 从已确认结果取得目标值，把真实总分与显示计数分离。计数每次刷新不能再次累计真实分数或发奖。
2. 只驱动显示值向目标收敛；DNv1TB93uxh 可见中间值递增到 10000 与完成文字逐字出现，不把中间值当作单次得分事件。时长与曲线由项目决定。
3. 如项目支持跳过，直接显示准确终值；重复打开仍读取同一结果，不重新触发真实结算。
4. 离开界面时清理计数与文字效果；镜头交接、控制归属和尾声由完成事件组合入口处理，不由数字动画决定。

## 适用限制

- DNv1TB93uxh 只有新增计数动画的字幕与新展示，没有旧版 A/B；more engaging 是作者目标，不是已测收益。
- 时长、速度曲线/easing、计分公式、跳过与完成/失败规则未核验，不补齐不完整字幕。1520、3498、10000 是本次画面分数，不是推荐计数速度或奖励量。
- 未读或运行代码，音频未核听；结果绑定、跳过与幂等要求是迁移建议，不是来源已实现证据。

## 验收

- [ ] 正常完成、支持的跳过和重复打开后，显示终值均与同一权威结果一致。
- [ ] 动画更新、重复播放和重开不重复计分/发奖，显示初值与目标值符合项目规则。
- [ ] 离开/中断后没有旧计数或文字效果；完成与失败按既定规则分别检查，不从来源推定两者同样结算。
