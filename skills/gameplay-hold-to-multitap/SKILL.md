# 用多次轻点替代按住输入

## 触发与范围

玩家难以持续按住按钮，希望对明确支持的动作选择多次轻点，而不是取消原操作。先从一个有清楚完成边界的按住交互接入，再按逐动作契约扩展；不建立覆盖全部输入的自动转换器，不引入 QTE、节拍考验或默认快速连点要求。

只有进度/提示显示错误时走[交互状态与提交反馈](../gameplay-contextual-ui/SKILL.md)。输入后动画响应迟缓走[动作相位](../gameplay-action-timing/SKILL.md)，提前按跳保留到落地走[跳跃输入缓冲](../gameplay-jump-input-buffer/SKILL.md)，按住时长改变跳高走[跳跃高度控制](../gameplay-variable-jump-height/SKILL.md)。

## 输入与前置决策

取得待支持动作清单、原按住路径、映射后的按下/松开事件、键盘自动重复识别、目标与动作实例身份、真实可执行条件、进度和提交接口、取消/失效事件，以及暂停、失焦与设置变更通知。

逐动作确认以下契约后才能启用替代入口：

- 按住究竟只是完成输入的方法，还是决定持续防御、充能大小、跳跃轨迹、危险暴露或其他玩法时间。后者需要项目另行定义替代语义，不能由本适配器猜测。
- 一次有效轻点如何推进、何时算输入完成、间隔是否允许无限长、暂停或目标暂时不可用时是否保留。次数、每次贡献、超时和衰减均为项目选择，不填通用数值；不因“多次轻点”而必设节奏窗口。
- 输入完成后仍需满足哪些独立玩法条件；两种入口的时长、成本、冷却及效果哪些必须相同、哪些允许变化。只共享动作结果不能推断全部时序相等。
- 取消方式、进度反馈、完成后如何开始下一次合法尝试；可重复动作尤其需要定义完成边界前的排队输入与边界后的新按下，不假定能从输入意图读出“尾部轻点”。

缺少这些决定时，先完成动作盘点和接口拆分，保留按住可用；指出待确认项，不上线自行假定的连点、开关保持或充能替代规则。

## 实施流程

1. 记录原按住流程的输入、目标、进度、提交与实际结果。将按钮保持检测从业务执行分开，使按住和轻点两种输入策略都向同一个动作处理器提交意图；目标合法性、资源扣除、冷却与实际效果仍由原权威处理器负责。若原完成条件把按住时长写死在业务代码中，只拆出已确认可替换的输入条件，不移除独立玩法期限或资格校验。
2. 增加可退出的多次轻点选项，并维护明确的支持动作清单。未开启时走原按住路径；开启后仅已登记动作使用轻点策略。未支持动作保持原方式并正确提示，不能显示“全部支持”。保留原按住实现和回切入口。
3. 每次尝试绑定动作实例、目标实例/版本、控制者及本次输入策略。策略在尝试期间唯一：同一输入不能既推动保持计时又累计轻点，两个设备映射到同一动作也不能绕过这一约束。适配状态可为未开始、收集中、等待权威结果、已结束；本次进度只属于该实例，不挂在一个可跨目标复用的全局计数器上。
4. 在现有输入映射之后识别有效按下边沿。一次按下到释放最多产生一个轻点事件，持续保持、系统自动重复和同一事件的重复派发不得增加次数；再一次轻点须有真实释放与新的按下。以事件身份去重，不用任意最小时间间隔拒绝真实操作。按键重映射和设备切换仍走同一逻辑动作，不写死物理键。
5. 将有效轻点交给该动作选定的输入策略。例如项目可以选“累计到指定次数后产生一次完成意图”，也可以选“每次增加已批准的交互进度”；只实现已选分支，不默认混合，也不把一次轻点伪造为若干秒持续保持。若使用中断窗口或衰减，明确时钟、暂停语义和实际提示；无此需求则不强加速度压力。进度由该策略或权威动作单一拥有，显示只读取，不自行再累加。
6. 输入条件满足时，先把本次尝试封口为等待结果，再向既有处理器提交一次带尝试标识的完成意图。处理器重新验证目标、资格和尚未消费的尝试，按原业务路径执行并回报成功/拒绝；若需等待既定玩法期限，则等待其真实满足。等待时忽略后续轻点，不把满格当成功。重复通知或迟到回调不能再次扣资源、发奖励或启动动作。
7. 成功、取消或拒绝后终止该尝试，清除其局部进度和完成边界前已排队的输入。后续尝试按逐动作声明的重新激活规则开始：可用焦点重入、明确重新开始或新的可交互阶段；同目标可重复动作也可允许完成边界后、确认释放后的全新按下启动。需要防尾部误触时选择额外确认或结束锁存，但不能对所有动作强制离开焦点，也不能把旧队列边沿当新输入。登记新尝试身份后才收集下一轮；旧回调不得改写当前实例结果。
8. 目标切换/销毁、控制权丢失时立即使旧尝试失效；旧进度不迁移到新目标，新目标也不消费已经排队的轻点。暂停、失焦、模式变更和重映射按已声明规则暂停或取消：保留时只能绑定仍有效的同一实例；取消时清理旧状态。设置切换可选择安全地取消后重开，或延迟到下一次尝试生效，不按未知比例换算保持时长与轻点次数。恢复时清除合成/陈旧边沿，重新同步设备当前按键状态：已松开则直接准备接收下一次全新按下；仍按住则等待释放后再接受新按下。没有可靠状态快照时先取得中立状态，不能把失焦期间漏掉的释放当成永远按住，也不能用恢复事件合成一次轻点。

## 提示与调参

提示跟随当前动作的有效策略和实时映射，清楚区分“按住”“多次轻点”“等待结果”和拒绝/取消。只有策略确实提供可解释的进度时才显示计数或进度条；没有节奏要求就不要写“快速连点”。成功提示只订阅权威结果，表现细节复用[交互状态与提交反馈](../gameplay-contextual-ui/SKILL.md)。

先以较慢、不均匀间隔验证操作能否按所选规则完成，再调整项目指定次数/单次贡献与取消容忍；最后检查成本、时长和提示。大量轻点本身可能增加操作负担，不把次数增加当成无障碍改进，也不声称这种方式适合所有玩家。任何最短完成时长或速度上限都须有明确玩法理由并独立测试，不从原按住时长推导一个“等价连点频率”。

## 失败定位与验收

- [ ] 关闭选项后原按住路径、取消和结果不变；开启后仅支持动作接受轻点。持续防御、跳高及未定语义的蓄力不会被自动改写。
- [ ] 慢速、不均匀、快速轻点都符合已声明规则；没有未声明的速度要求。长按、自动重复及双设备重复事件不冒充多次轻点，不同时推进两套策略。
- [ ] 同一目标的输入完成至权威结果全过程最多提交并生效一次。等待中的额外轻点、完成前的排队边沿和旧回调不再提交；完成/取消后的全新输入仅按已声明的重新激活规则开始下一次。
- [ ] 在目标 A 已有进度时换到 B、销毁 A、切换控制权，再送达 A 的旧事件，B 的进度与结果均不受影响；同一对象复用也核对实例版本。
- [ ] 模式切换、重映射、暂停/恢复、窗口失焦及释放后重入不留下半按状态、旧进度或合成按下；恢复时已松开的键不会吞掉下一次合法按下；重新开始条件会丢弃旧队列，同时允许项目明确支持的下一次操作。
- [ ] 对同一合法动作对照两种输入的实际结果、资源、冷却与时长，分别满足项目契约；拒绝和取消不播成功。未运行目标项目测试时不得把该清单标成通过。

若轻点被丢弃，先查边沿采样、自动重复过滤和目标实例归属，不先要求玩家按得更快。若进度翻倍，查两策略并行与多处写进度；若旧队列触发下一次，查完成边界与重开条件；若更换目标仍完成旧操作，查实例失效及迟到回调。无法满足既定动作语义时，仅关闭该动作的替代映射并保留原按住路线，不靠放宽资格或跳过业务条件“修好”。

需要核对出处、未知项或独立边界时，读取[来源参考](references/sources.md)。
