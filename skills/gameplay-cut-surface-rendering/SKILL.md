# 切割新表面的封口与材质边界

来源包含前期封口制作和后期材质边界修正，未证明完整切割系统。以下是按这两个阶段整理的迁移与验收流程，不是作者代码复刻。

## 触发条件

- 游戏中的切断已发生，但新截面敞开、看起来中空，或被错误地铺上全部外皮。
- 已有截面填面，但内部材质仍是固定圆形，不能跟随分叉等不规则边界。

## 先确认的输入

切割系统实际输出的截面边界与新面、需要封口的对象/面、内外材质分配、当前法线/UV/顶点色数据、支持的切割形状范围。先查实际几何，不从截图补边界排序、三角化、顶点权重或 shader 公式。

## 分步机制

1. 区分三个问题：是否缺新表面、材质是否分配到正确面、边界过渡是否贴合轮廓。先解决缺面和归属，再判断是否需要修边；不要用更漂亮的纹理掩盖开放截面。
2. 缺封口时，检查现有切割输出能否提供有效边界，并选用项目支持的填面方法。支持帖 DVwEG5BDTKl 显示边点/中心标记到填面，作者描述新网格和子网格；它没有证明任意凹轮廓或多边界均可用中心点扇形连接。算法能力不足时先限制支持范围或另行验证，不把演示连线当通用实现。
3. 将新暴露面与原外表面的材质职责分开，校对实际生成面、子网格和材质槽。支持帖可见 Material Element 0 / 1，但槽位数字不是通用树皮/木芯约定，也不能据此确认所有面分配正确。
4. 需要外皮与内部过渡时，让过渡依据实际截面形状而不是固定圆形。主帖 DV1QmLcjaf5 展示错误圆芯、不规则轮廓上的红内黑外 Vertex Colors，以及后续木芯/窄树皮边；可据此考虑顶点数据承载混合权重，但具体通道、计算方式、宽度与 shader 均须在项目中确定。
5. 分别查看封口、材质分配和边缘过渡的结果。对项目支持的切角、分叉及再次切割检查接缝和退化形状；切断事件/碰撞仍由既有系统管理，视觉封口成功不等于物理断裂或所有几何均正确。

## 适用限制

- 主帖实见不规则木截面、错误圆芯、Vertex Colors 显示与随后贴合轮廓的木芯/窄树皮边；这是材质边界修正，不是用户偏好或“更自然”的实测结论。
- 支持帖的新网格、子网格和材质分工来自作者说明及有限编辑视图；显示的中心公式分母未读清，不据此推精确公式、边界排序、绕序或三角化正确性。
- 未核凹形/多环/孔洞处理、法线/UV 修复细节、顶点色计算、混合公式、噪声、边宽、碰撞体更新或运行成本。前后帖子分别支持各自阶段，不能拼成已验证的完备切割管线。
- 视觉无缺口不证明网格 watertight、流形正确或碰撞体封闭。没有执行作者代码、几何回归、性能或音频测试；下列检查是本库提出的实施验收。

## 验收

- [ ] 在明确支持的形状和观察方向内，新暴露面无意外缺口、反面消失或明显接缝；不支持的凹形/多环输入有明确处理，而不是默认成功。
- [ ] 内外材质只作用于目标面，原外表面未被覆盖；材质槽变动或再次切割不会错误沿用面索引。
- [ ] 不规则轮廓/分叉的内部材质和边缘跟随真实截面，不残留硬套的圆芯；过渡宽度与贴图比例由项目对照决定。
- [ ] 几何、法线/UV 和材质问题分开诊断；视觉修复不重复触发切断、产物结算或无意改变碰撞。
